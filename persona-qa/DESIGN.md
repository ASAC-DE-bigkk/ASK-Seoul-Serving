# 측정 설계 — 발표용

> "무엇을 어떻게 만들어서 쟀나"에 답하는 문서. 숫자를 어떻게 계산했는지는 [METHOD.md](METHOD.md),
> 회차별 결과는 [README.md](out/README.md).

## 한 장 요약

```
① 페르소나   NVIDIA Nemotron-Personas-Korea 에서 서울 거주자를 층화 추출   (LLM 없음)
② 질문       페르소나 프로필만 주고 생성 — 카탈로그는 숨긴다              (sonnet-5)
③ 실측       질문을 그대로 MCP 서비스에 던져 답변을 받는다                (sonnet-5)
④ 채점       답변을 읽고 5개 라벨 중 하나를 매긴다                        (haiku-4-5)
```

## ⚠️ 먼저 바로잡을 것 — 질문은 카탈로그를 **보지 않고** 만들었다

"질문은 마켓플레이스에 공개된 카탈로그를 바탕으로 만들었다"고 말하면 **정반대이고, 그 순간
커버리지 숫자가 의미를 잃는다.**

우리가 가진 제품 목록을 보여주고 질문을 만들면 "우리가 답할 수 있는 질문"만 나온다.
그러면 커버리지는 100%에 가까워지고 아무것도 측정하지 못한다.
**카탈로그를 모르는 상태에서 나온 질문이라야 "실제 수요 중 몇 %를 커버하나"를 잴 수 있다.**

실제 프롬프트에 들어가는 것은 페르소나 프로필뿐이다([`02_generate_questions.py`](scripts/02_generate_questions.py)):

```
아래는 서울에 사는 한 인물의 프로필이다.
- 43세 여자, 성북구 거주
- 직업: 한식 조리사 / 학력: … / 기혼
- 취미: …
- 소개: (Nemotron 원문 300자)

이 인물이 일상·일·취미 속에서 "서울에 관한 데이터"로 답을 얻을 수 있을 법한
궁금증 3가지를 이 인물의 입말로 작성하라. 조건:
- 주제는 상권·창업, 도시생활, 문화행사, 도로교통, 대중교통, 날씨 중에서
  이 인물에게 자연스러운 것만 고른다
- 특정 서비스나 데이터셋 이름을 언급하지 않는다
```

제품 목록·컬럼·필터 축은 **한 글자도 들어가지 않는다.** 6개 도메인 이름만 힌트로 주는데,
이건 "서울 공공데이터로 답할 만한 주제"라는 범위 안내이지 카탈로그가 아니다.

> **발표에서 이렇게 말할 것** — "질문은 카탈로그를 숨긴 채, 페르소나의 나이·직업·동네·취미만
> 보고 만들었습니다. 우리가 답할 수 있는 질문만 골라 물으면 측정이 되지 않기 때문입니다."

## ① 페르소나 — NVIDIA 데이터셋에서 층화 추출

| | |
|---|---|
| 원천 | **`nvidia/Nemotron-Personas-Korea`** (HuggingFace) |
| 규모 | 전체 100만 명 → 그중 **서울 거주자 185,228명**이 모수 |
| 접근 | HuggingFace datasets-server API — 전체 다운로드 없음, **LLM 호출 없음** |
| 추출 | 연령 5구간(20대/30대/40대/50-64/65+) 균등 + 성별 5:5 + 직업 중복 회피 + 자치구 편중 완화 |
| 재현 | **시드 고정** — 같은 시드로 다시 돌리면 같은 사람이 뽑힌다(v4에서 UUID 순서까지 일치 확인) |
| 쓰는 속성 | 나이·성별·자치구·직업·학력·혼인상태·가구형태·취미·인물 소개 |

**회차마다 완전히 새로운 사람을 뽑는다.** 앞 회차에서 쓴 UUID를 제외 목록으로 넘겨,
"이미 아는 사람에게 맞춰 고친 것 아니냐"는 의심을 설계로 차단한다.

| 회차 | 인원 | 연령 분포 | 성별 | 자치구 | 직업 |
|---|---|---|---|---|---|
| 1·2차 | **77명** | 16·16·15·15·15 | 39:38 | 23종 | 60종 |
| 3차 | **20명** | 4·4·4·4·4 | 10:10 | 13종 | 16종 |
| 4차 | **40명** | 8·8·8·8·8 | 20:20 | 22종 | 36종 |

(1차 77명 = 최초 50명(시드 42) + 추가 27명(시드 43). 2차는 이 77명 중 20명을 재사용.
3차는 1·2차 77명 제외, 4차는 97명 전원 제외.)

## ② 질문 — 페르소나당 3문항

`claude-sonnet-5` 가 프로필만 보고 생성한다. 누적 **411문항**(1차 231 · 3차 60 · 4차 120,
2차는 1차 문항 60개 재사용). 전 회차 목록은 [`shared/all-personas-questions.csv`](out/shared/all-personas-questions.csv).

질문은 "이 인물의 입말"로 나온다 — 예:

> "새벽같이 현장 나가려면 첫차를 타야 하는데, 강서구에서 그 시간에 다니는 버스가 있는지 궁금하네"
> — 66세 남성 · 강서구 · 형틀 목공

## ③ 모델 — 단계마다 다르다

"sonnet 기반"은 절반만 맞다. **채점은 haiku가 했다.**

| 단계 | 모델 | 왜 |
|---|---|---|
| ① 페르소나 추출 | **없음** | HuggingFace API 조회 + 결정적 선별 규칙 |
| ② 질문 생성 | `claude-sonnet-5` | |
| ③ 실측(답변 생성) | `claude-sonnet-5` (2·3·4차)<br>1차는 혼합 — haiku 156 · cli기본 41 · sonnet 34 | 1차는 세션 한도로 중간에 모델을 바꿔야 했다 |
| ④ 채점 | **`claude-haiku-4-5`** (전 회차 동일) | 회차마다 판정자를 바꾸면 라벨 분포가 판정자 때문에 움직인 건지 서비스 때문인지 갈라낼 수 없다 |

> **발표에서 이렇게 말할 것** — "질문 생성과 답변 생성은 sonnet-5, 채점은 haiku-4-5입니다.
> 채점자를 고정한 건 회차 간 비교 가능성을 지키기 위해서입니다."

## ④ 응답 — MCP 경유 API 데이터에 근거한 답변

정확히는 **"API 응답을 그대로 보여준 것"이 아니라 "API 응답을 근거로 LLM이 작성한 답변"**이다.
서비스가 실제로 그렇게 동작하므로, 그 형태 그대로 잰다.

```
질문 → headless Claude(sonnet-5) → 원격 MCP(https://ask-seoul.kr/mcp)
      → search_products / describe_product / query_product / run_pattern …
      → 조회한 행을 근거로 자연어 답변 작성
```

MCP 서버가 돌려주는 데이터는 REST API(`/api/v1/data/…`)와 같은 원천이다.
카탈로그(`/api/v1/catalog`)는 인증 없이 공개되지만 **실제 데이터 행은 키가 있어야 조회된다**.

**"정말 API 데이터만 썼나"를 검증했다.** 실측 세션이 로컬 파일(Bash·Grep 등)을 뒤지면
그 전제가 깨지므로, 툴 호출 로그로 잰다:

| 회차 | 로컬 툴 차단 | **실제 개입** |
|---|---|---|
| 1차 | 없음 | **35.5% (82/231)** ← 문항 3분의 1이 오염 |
| 2차 | 없음 | 3.3% (2/60) |
| 3차 | 없음 | 6.7% (4/60) |
| **4차** | **있음** | **0% (0/80)** |

4차부터 `--disallowedTools` 로 로컬 툴을 실제로 막았다. 차단 시도 4건이 로그에 남지만
전부 `"not enabled in this context"` 로 거부됐다 — **오염 0건**이다.

> **발표에서 이렇게 말할 것** — "답변은 MCP를 통해 조회한 API 데이터를 근거로 생성됩니다.
> 4차부터는 로컬 도구를 차단해 외부 데이터가 섞일 여지를 없앴고, 실측 결과 오염 0건입니다."
