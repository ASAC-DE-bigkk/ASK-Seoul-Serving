# qa-lab 대시보드 비교 화면 — 테스트 절차

기존형(`query_product`)↔신설형(`run_pattern`) as-is/to-be 비교 화면의 순차 절차다.
전체 흐름(키 발급·마켓 콘솔·식별자 로그 확인·정리)은 마스터 매뉴얼
[`marketplace/public/qa-lab/TESTING.md`](../../../marketplace/public/qa-lab/TESTING.md) 를 본다.

> 부가물이다 — 이 폴더를 지우면 함께 사라진다. 콘솔 근간(index.html·ui.css·ui.js)은 무수정.

## 접속

| 환경 | 주소 | 게이트웨이 주소(base) 칸 |
| --- | --- | --- |
| 서비스(배포) | https://ops.ask-seoul.kr/qa-lab/ | `https://ask-seoul.kr` (기본값) |
| 로컬 | http://localhost:8788/qa-lab/ (`cd ops-dashboard && npm run dev`) | `http://localhost:8787` (마켓 로컬) |
| wrangler 없이 | `index.html` 파일 더블클릭 | `https://ask-seoul.kr` |

- 이 화면은 게이트웨이와 **다른 출처(교차 출처)** 다. `/api/v1/*` 는 `Access-Control-Allow-Origin: *`
  라 교차 출처 조회가 되지만, **커스텀 헤더(`X-ASK-Intent`)를 실으면 CORS 프리플라이트가 뜨고**
  게이트웨이 OPTIONS 가 그 헤더를 불허해 **실패한다("Failed to fetch")**. 그래서 이 화면은
  **교차 출처일 때 식별자 헤더를 자동으로 뺀다**(단순 요청 → 정상). 마커 `max20_fable` 는 동일
  출처인 마켓 랩·MCP `initialize` 가 남긴다.
- 신설형 라이브 실행(`/mcp`)은 응답에 CORS 헤더가 없어 교차 출처로는 막힌다 → 마켓 콘솔 결과를
  붙여넣어 반영한다(아래 6). 또는 CLI 직접 연결(마스터 매뉴얼 §D)로 검증한다.

> ⚠️ **"Failed to fetch / 로드 실패"가 떴다면**: (1) base 가 실행 환경과 맞는지 —
> 배포에서 봤으면 `https://ask-seoul.kr`, 로컬이면 `http://localhost:8787`. (2) 위 헤더-프리플라이트
> 이슈는 코드에서 이미 교차 출처 헤더를 빼도록 고쳤다(재배포 반영 필요).

## 순차 절차

1. **base 주소 확인** → **카탈로그 불러와 비교 시작** 클릭.
   - `제품 N종 로드됨` 이 뜨고 아래 두 카드가 나타나면 성공.
2. **헤드라인(1번 카드)** 확인 — 두 큰 숫자:
   - "기존형으로 답 가능 %" vs "신설형 필요 %" (실측 대략 **1.2% vs 98.8%**).
3. **능력별 막대** — `sort`·`aggregate`·`group_by`·`filter_set(P3)`·`join(P7)` … 각 능력을 요구하는
   패턴 비율. **빨강 = 기존형이 서버에서 미지원**하는 능력.
4. **질문 하나로 나란히 보기(2번 카드)** — 제품·패턴 선택:
   - 좌(기존형·AS-IS): 이 질문이 요구하는 능력 칩(빨강=미지원) + "답 불가/부분/가능" 판정.
   - 우(신설형·TO-BE): pattern_id 1개 선택 = 답 · `verified_at`/`verified_rows` · `insight` 예시.
   - 하단 **지표 표**: 요청 범위·답변 범위·AI 질의 접근성·정보 제공 정확성·답 가능 여부.
5. (API 키 있으면) **기존형 라이브 조회** 클릭 → `/api/v1/data` 로 원시 행 수를 실측해
   "AS-IS는 답이 아니라 재료(원시 행)"임을 수치로 확인.
6. (선택) **신설형 라이브 반영**:
   1. 마켓 콘솔(https://ask-seoul.kr/qa-lab/)에서 같은 제품·패턴으로 `run_pattern` 실행.
   2. "대시보드 비교용으로 복사" 클릭(클립보드로 JSON).
   3. 이 화면 하단 "신설형 라이브 결과 붙여넣기" 칸에 붙여넣고 **반영** → 신설형 라이브 행 수가 지표에 반영.

## 확인 포인트

- [ ] 카탈로그 로드 후 헤드라인 두 숫자와 능력별 막대가 뜬다.
- [ ] 집계·정렬형 질문에서 좌측이 "답 불가", 우측이 "가능" 으로 갈린다.
- [ ] (키) 기존형 라이브 조회가 원시 행 수를 반환한다.
- [ ] 붙여넣기로 신설형 라이브 행 수가 반영된다.

모든 게이트웨이 호출에 `X-ASK-Intent: max20_fable` 가 실린다 — 콘솔 '이용 행동' 탭에서 식별 가능.
