| | |

| **누가** | 콘솔(ops-dashboard). route 값 **자체**는 게이트웨이 소유라 여기서 정하지 않는다 |
| **언제** | 2026-08-05. 게이트웨이가 MCP 를 툴별로 가른 뒤(`01106fb`, #75) |

| **어떻게** | 조건을 한 곳에 모으고, 배열 하나를 정본으로 삼아 SQL 과 `meta` 를 **거기서 만든다** |

## 이 문서가 정하지 않는 것

**route 값 자체**(어떤 문이 어떤 값을 내보내는가)는 게이트웨이·MCP 소유다. 여기서는 **이미
내보내진 값을 소비하는 규칙**만 정한다. 값이 늘면 이 문서가 따라간다 — 반대가 아니다.

## 왜 — 조건이 흩어져 있으면 새 문이 생길 때마다 조용히 틀린다

#63 이 잡은 사고의 뿌리는 `route='data'` 라는 조건이 **다섯 군데 흩어져 있던 것**이다.
`/skill/v1` 이 붙었을 때 다섯 곳을 다 고쳐야 했는데 아무 데도 안 고쳤고, 화면은 오류 없이
**낮은 숫자**를 보여줬다. 틀린 값은 빈 값보다 나쁘다 — 빈 값은 사람이 의심하지만 낮은
값은 그냥 읽힌다.

그래서 이 문서의 형식이 목록이다. **"어디를 고쳐야 하나"에 한 곳으로 답할 수 있어야** 같은
사고가 안 난다.

## 1. 값 → 화면 문구 (`ROUTE_KO` 정본, 17종)

`public/index.html` 의 `ROUTE_KO` 가 구현이고, 이 표가 정본이다.

| route | 화면 문구 | 비고 |
|---|---|---|
| `catalog` | API 목록 | |
| `preview` | 미리보기 | |
| `data` | 데이터 조회 | **SERVE** |
| `me` | 내 사용량 | |
| `keys` | 키 발급 | |
| `revoke` | 키 폐기 | 예전엔 `keys` 와 한 덩어리였다 |
| `product` | 제품 번들 | ⚠️ **`v1_product` 아니다** — `ea28bcc`(#67) 개명 |
| `glossary` | 용어 사전 | ⚠️ **`v1_glossary` 아니다** — 〃 |
| `skill_bundle` | 스킬 묶음 | |
| `skill_data` | 스킬 데이터 조회 | **SERVE** |
| `skill_product` | 스킬 제품 안내 | |
| `mcp` | **AI 연결 준비** | 연결 절차만(initialize · tools/list · notifications) |
| `mcp_list_products` | AI 목록 조회 | |
| `mcp_describe_product` | AI 제품 안내 | |
| `mcp_preview_product` | AI 미리보기 | |
| `mcp_query_product` | AI 데이터 조회 | **SERVE** |

| `mcp_check_quota` | AI 사용량 조회 | |
| `auth_start` | 로그인 시작 | Google OAuth 로 넘기는 302 (#110 ②) |
| `auth_callback` | 로그인 완료·키 발급 | 확인된 이메일로 키를 발급. **`keys` 를 대체**한다 — 배포 환경에서 `keys` 는 403 으로 닫힌다 |

**이름은 문 단위가 아니라 "무엇을 했나" 단위로 맞춘다.** MCP 로 들어온 호출은 REST 와 하는
일이 같고 부르는 함수도 같다(#63 실측 표) — 사람에게는 *경로가 다른 같은 일*이라 그렇게
읽혀야 한다. `mcp_query_product` 를 "AI 데이터 조회"로 적는 이유가 이것이다.

> **`mcp` 의 문구를 바꾼 이유.** 이 값은 툴 세분화 전에는 MCP 전부를 뜻해서 "AI 연결(MCP)"
> 이 맞았다. 지금은 **연결 절차만** 남았으므로 그 문구는 기능 호출까지 품는 **틀린 말**이
> 된다. 값의 뜻이 바뀌면 문구도 바뀐다 — 값이 그대로라고 문구를 두면 그게 거짓말이다.

### 1-1. 퇴역한 값도 싣는다 — **로그는 개명보다 오래 산다**

| route | 화면 문구 | 언제 퇴역 |
|---|---|---|
| `v1_product` | 제품 번들 | `ea28bcc`(#67) — `product` 로 개명 |
| `v1_glossary` | 용어 사전 | 〃 — `glossary` 로 개명 |

라우터가 더는 안 내보내도 **과거 행에는 남아 있다.** 이 표를 "게이트웨이가 지금 내는 값"
17종으로만 채웠더니 검증에서 `v1_product` **16건이 화면에 날것으로 나왔다** — 조회창이
개명 시점을 걸쳤기 때문이다.

**번역표가 덮어야 하는 것은 '라우터가 내는 값'이 아니라 '로그에 있을 수 있는 값'이다.**
#63 본문이 *"게이트웨이가 실제로 쓰는 값"* 이라고 범위를 잡은 것 자체가 좁았다.

새 이름과 **같은 문구**를 쓴다 — 사람에게는 같은 문이고, 이름이 바뀐 건 우리 사정이다.
로그 보존 기간이 지나 그 행이 사라지면 그때 지운다(그 전에 지우면 슬러그가 샌다).

**표에 없는 값이 화면에 뜨면 그건 버그다.** 폴백 `ROUTE_KO[r.route] || esc(r.route)` 는
슬러그를 그대로 보이므로, 회귀 검증(§5)에서 노출 0개를 확인한다.

## 2. `SERVE` — 무엇을 "데이터를 서빙한 호출"로 세나

```js
const SERVE_ROUTES = ["data", "skill_data", "mcp_query_product", "mcp_run_pattern"];
const SERVE = "route IN (" + SERVE_ROUTES.map((r) => "'" + r + "'").join(", ") + ")";
```

**판정 기준은 "데이터를 돌려주는가"이지 문이 아니다.** `mcp_run_pattern` 이 여기 들어간 것도
새 판단이 아니라 이 기준의 적용이다 — 검증된 패턴 SQL 을 서버가 돌려 **행을 반환하고 쿼터를
1회 차감한다.** 툴이 늘 때마다 이 문단이 답을 준다.

**배열이 정본이고 SQL 은 거기서 만든다.** 화면에 알리는 `meta.serve_routes` 와 질의 조건을
따로 적으면 언젠가 어긋나고, 그때 화면은 "이렇게 셌습니다"라고 **틀린 말**을 하게 된다.

쓰는 곳은 다섯이다 — 제품별 수요 · 키 활성화 판정(2곳) · 에이전트별 데이터 호출 · API 사용량.
**새 문이 생기면 배열만 고친다.**

포함 기준은 **"데이터 행을 실제로 돌려줬나"** 하나다.

| 뺀 값 | 왜 |
|---|---|
| `preview` · `mcp_preview_product` | 판단 재료다. 일일 쿼터도 안 깎는다 |
| `product` · `glossary` · `skill_product` · `mcp_describe_product` | 메타·안내 |
| `catalog` · `mcp_list_products` | 목록 |
| `me` · `mcp_check_quota` · `keys` · `revoke` | 데이터와 무관 |
| `mcp` | 연결 절차 — **§3 참조** |

### 2-1. 키 활성화 판정도 같은 축을 쓴다 — 의도한 것이다

`first_call`·`first_data_call` 이 `SERVE` 를 쓰므로 **`mcp_query_product` 가 키를 활성화된
것으로 만든다.** 부작용이 아니라 의도다 — AI 로 데이터를 받아 간 키는 **쓰인 키**다.
문으로 갈라 세면 "MCP 로만 쓰는 키"가 영원히 미활성으로 남아 활성화율이 낮게 나온다.

## 3. 맨 `mcp` 에는 두 가지가 섞여 있고, **가르는 것은 `status` 다**

| 조건 | 정체 | 처분 |
|---|---|---|
| `route='mcp'` · `status < 400` | 연결 절차(initialize · tools/list · notifications) | **뺀다.** 못 가른 게 아니라 **셀 것이 아니다** |
| `route='mcp'` · `status >= 400` | 🔴 버스트로 **거부된 tool 호출** | **뺀다. 그리고 뺐다고 화면이 말한다** |

### 3-1. 🔴 거부된 데이터 호출이 툴 이름을 안 남긴다 (게이트웨이 미해결)

`mcp.js` 가 route 를 `callTool` 진입에서 정하는데 **그 자리가 버스트 뒤**다.

```
handleMcp: 인증 → checkBurst  ──(초과)──▶ burstProblem 반환        route = 'mcp'
                     │                                             ↑ :212-213
                     └─▶ callTool ─▶ trace.route = `mcp_${name}`   route = 'mcp_query_product'
                                      ↑ :120 (호출은 :215)
```

같은 툴을 부른 요청인데 **통과하면 `mcp_query_product`, 막히면 `mcp`** 로 갈린다. REST 는
라우터가 버스트 **앞**에서 정해 429 여도 `data` 로 남으므로 **MCP 만 다르다**
(@yooseongjin527 실측: 통과 60 / 거부 4).

**콘솔의 처분: 빼고, 뺀 건수를 화면이 말한다**(`meta.mcp.unsplit`). 짐작해서 채우면 부풀고,
침묵하면 "AI 로는 안 쓰인다"로 읽힌다 — 후자는 관측 공백을 이상 없음으로 위장하는 것이다
(agreement §4). 게이트웨이가 그 한 줄을 버스트 앞으로 옮기면 **값이 0이 되어 안내가 저절로
꺼진다** — 콘솔은 고칠 것이 없다.

### 3-2. 제품 축에서는 세지 않는다

막힌 요청은 핸들러에 못 가서 **제품을 안 남긴다.** 제품별로 세면 언제나 0이고, 그 0은
"이 제품은 괜찮다"는 **틀린 안심**이 된다. 그래서 창 전체(`meta.mcp`)에서만 말한다.

## 4. 가르기 전 기록 — 폴백이 불가능하다

`01106fb` **이전** 행은 `query_product` 도 전부 `route='mcp'` 다. 기본 조회창이 14일이라
**한 화면 안에 두 규약이 섞인다.**

제품 축의 `product_id` NULL 을 `table_name` 으로 폴백한 것(§0003)과 같은 종류로 보이지만
**다르다** — 옛 `mcp` 행에는 툴을 복원할 단서가 없다. `intent` 는 선택값이라 못 쓴다.
**되살릴 수 없는 것은 되살리는 척하지 않는다.**

판정은 **날짜를 박지 않고 실측으로** 한다:

```
mcp_split_from = MIN(ts) of  route LIKE 'mcp\_%'      -- 갈린 행 중 가장 이른 것
mcp_bare_first = MIN(ts) of  route = 'mcp'            -- 안 갈린 행 중 가장 이른 것
pre_split      = 둘 다 있고  mcp_bare_first < mcp_split_from
```

`pre_split` 이면 화면이 **"이 기간 앞부분은 기능별로 가르기 전 기록"** 이라고 밝히고,
**기간을 좁히면 사라진다**는 것까지 알려 준다. 창이 규약 이후로만 채워지면 안내는 저절로
꺼진다 — 하드코딩한 날짜가 없으므로 관리할 것도 없다.

> 창에 갈린 행이 하나도 없으면 `pre_split` 은 **false** 다. "가르기 전"인지 "MCP 를 안 썼는지"
> 구분할 수 없기 때문이다. **모르는 것을 단정하지 않는다** — 없는 경고를 띄우는 것도 거짓말이다.

## 5. `meta` 계약

| 필드 | 뜻 |
|---|---|
| `meta.serve_routes` | `SERVE_ROUTES` 그대로. 화면이 "무엇을 데이터 서빙으로 셌나"를 말할 근거 |
| `meta.mcp.unsplit` | 거부돼 툴을 못 남긴 건수(§3-1). **0이면 안내가 안 뜬다** |
| `meta.mcp.pre_split` | 창에 가르기 전 기록이 섞였나(§4) |
| `meta.mcp.split_from` | 툴별로 갈리기 시작한 시각(실측). 창에 갈린 행이 없으면 `null` |

> `meta.mcp_calls` 는 **없앴다.** "MCP 전체가 못 가름"이라는 뜻이었는데 이제 사실이 아니다.
> 필드를 남겨 두면 뜻만 바뀌어 조용히 오독된다 — [runbook §2](../runbook.md) 의 `jq` 예시를 같이 고쳤다.

| 확인 | 통과 기준 |
|---|---|
| 화면의 내부 슬러그 노출 | 18종 다 태운 뒤 **0개** (`mcp_run_pattern` 추가) |

## 대가

- **화면 문구가 늘었다.** 요청 종류가 17줄까지 늘 수 있다. 묶어서 줄이지 않은 이유는
  #63 결정 A 의 목적이 *발견 → 확인 → 서빙* 퍼널 관측이라, 묶는 순간 그게 도로 안 보인다.
- **`ROUTE_KO` 는 손으로 맞춰야 한다.** 게이트웨이가 값을 늘리면 콘솔이 따라가야 하고,
  자동 동기화 장치는 없다(두 워커가 코드를 공유하지 않는다 — [0001](0001-separate-worker-from-marketplace.md)).
  대신 **빠지면 화면에 슬러그로 드러나므로** 조용히 틀리지는 않는다.
- **`pre_split` 안내는 창을 넓힐수록 잘 뜬다.** 90일로 보면 한동안 계속 뜬다 — 성가시지만
  그 구간의 숫자가 실제로 낮으므로 맞는 말이다.

## 재검토 조건

- 게이트웨이가 `mcp.js` 의 route 대입을 **버스트 앞으로** 옮기면 → §3-1 을 지운다.
  코드는 그대로 둔다(`unsplit` 이 0이 되어 안내가 저절로 꺼진다)
- route 값이 늘거나 이름이 바뀌면 → §1 표와 `ROUTE_KO` 를 **같은 커밋에서** 고친다
- MCP 가 아닌 새 표면이 데이터를 서빙하면 → `SERVE_ROUTES` 에 추가(그곳 한 곳만)
- 로그 보존 기간이 지나 `01106fb` 이전 행이 사라지면 → §4 는 자연히 무효가 된다(코드는 유지)
