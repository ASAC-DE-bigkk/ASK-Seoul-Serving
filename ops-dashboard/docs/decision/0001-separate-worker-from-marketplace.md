# 0001 — 마켓플레이스와 다른 Worker · 다른 호스트로 분리한다

- 상태: **채택** (2026-07)
- 관련: [reference/](../reference/) 의 "운영 대시보드 별도 애플리케이션 분리" 항목

## 맥락

서빙 품질·키 관리 화면을 어디에 두느냐. 게이트웨이([../../../marketplace/](../../../marketplace/))에
`/admin` 경로로 붙이면 Worker 하나로 끝나고, 별도 Worker 로 떼면 설정(공유 상태)이 하나 늘어난다.

## 결정

**별도 Worker · 별도 호스트**로 둔다 — `ask-seoul-ops-dashboard`, 로컬 `:8788`
(게이트웨이는 `:8787`).

## 근거

- **청중이 다르다.** 저쪽은 외부 고객(키 발급·데이터 조회), 여기는 운영자(품질·조치).
- **배포 단위가 갈려야 사고 반경도 갈린다.** 콘솔 실수가 게이트웨이를 죽이지 못하고,
  게이트웨이 장애 중에도 콘솔은 뜬다(부분 강등, `meta.missing`).
- 인증 요구가 다르다 — 게이트웨이는 API Key, 여기는 운영자 토큰(→ [0004](0004-read-open-write-token.md)).

## 대가

- 로컬 D1 상태 공유 설정이 필요해졌다(`--persist-to`, → [0003](0003-single-shared-local-d1.md)).
- 로컬에서 프로세스를 두 개 띄워야 한다.

## 재검토 조건

없음 — 구조의 기초 결정. 합치자는 제안은 새 결정 문서로 사유부터 적는다.
