# 0007 — _ops_* 스키마 정본은 단일 파일 리셋

- 상태: **채택** (2026-07) — **팀 D1 승격 시점까지만 유효**
- 관련: [reference/](../reference/) 의 "D1 Migration 정책(증분·하위 호환)" 항목

## 맥락

프로토타입 단계라 `_ops_slo` 컬럼이 자주 는다(초록 위장 컬럼이 실사례). 증분 마이그레이션을
지금 시작하면 ALTER 가 누적되는데, 지킬 데이터가 없다.

## 결정

- **`migrations/0001_ops_slo.sql` 하나가 스키마 정본이다.** 컬럼이 늘면 ALTER 누적 대신
  DROP+CREATE 로 통째로 다시 만든다.
- 내용물은 로더(`scripts/load_slo.py`)나 픽스처(`npm run seed`)가 매번 다시 채우므로
  **잃을 상태가 없다** — 리셋이 공짜인 동안만 이 규약이 성립한다.

## 경계

- 이 규약은 **`_ops_slo`·`_ops_domain` 에만** 적용된다. 게이트웨이 소유 테이블은
  저쪽 migrations 가 정본이고 증분 규약을 따른다(→ [0003](0003-single-shared-local-d1.md)).

## 재검토 조건

**팀 D1 로 승격되는 순간 증분 마이그레이션으로 전환한다** — 그때부터는 잃을 상태가 생기고,
reference 문서의 "파괴적 Migration 과 코드 변경을 한 번에 배포하지 않는다" 원칙이 살아난다.
[0002](0002-local-only-mentor-gate.md) 개정과 같이 움직인다.
