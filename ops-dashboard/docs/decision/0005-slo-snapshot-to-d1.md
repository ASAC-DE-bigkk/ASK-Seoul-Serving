# 0005 — 파이프라인 상태는 **조회 DB** 에서 읽는다 (Trino 복사는 폐기 예정 폴백)

- 상태: **개정** (2026-08). 초판(2026-07)의 "Trino 마트를 복사한다"를 **정규 경로에서 내린다**
- 관련: [0003](0003-single-shared-local-d1.md)(공유 D1) · [0007](0007-schema-single-file-reset.md)(증분)
- 근거 규약: **ASK-Seoul#78** (§8 조회 DB · D-2) · 구현 **ASAC-DAG#647** · 검증 **#655**

## 정본은 파이프라인이 D1 에 싣는 실행 기록이다

콘솔이 파이프라인 상태를 보여주는 근거는 **파이프라인·dbt 가 실행 과정에서 D1 에 적재하는
운영 기록**이다. 웨어하우스(Trino)를 콘솔이 직접 훑는 구조가 아니다.

| 표 | 한 행이 무엇인가 | 자연키 |
|---|---|---|
| `_ops_run_event` | 실행 기록 1건 | `event_id` |
| `_ops_daily_metric` | 날짜×도메인×단계 집계 — **화면이 실제로 읽는 표** | (`observed_date_kst`, `domain`, `layer`) |
| `_ops_pipeline_state` | DAG 하나의 현재 상태 | `dag_id` |
| `_ops_pipeline_expectation` | DAG 하나의 기대치 | `dag_id` |

스키마 정본은 **ASAC-DAG `common/ops/d1_ops.py`** 이고 콘솔은 **읽기 전용 소비자**다
([0007](0007-schema-single-file-reset.md) 소유 표 참고).

**#78 D-2** — "기존 `_ops_slo`·`_ops_domain` 은 스키마를 바꾸지 않는다. 화면이 이미 쓰는
계약이며, **위 4종에서 값을 채운다**." 즉 `_ops_slo` 는 **화면 계약**으로 남기고, 그 값을
채우는 **공급자만** 조회 DB 4종으로 바꾼다.

적재는 이미 동작한다 — **#655**(2026-08-03)가 실제 조회 DB 에 표 4종 생성 · **52건 적재**
(citydata 35 · weather 6 · traffic 7 · transit 4) · 기대 주기 9행 등록을 확인했다.

## Trino 경로는 왜 있었나 (그리고 왜 내리나)

`scripts/load_slo.py`(Trino REST → `_ops_slo`)는 **이 규약이 서기 전**의 우회로다. 당시엔
파이프라인이 D1 에 기록을 싣지 않았고, 콘솔이 파이프라인 품질을 보려면 웨어하우스의
`gold_*_slo_daily` 를 복사하는 방법밖에 없었다(Trino 는 `http://trino:8080`, Docker 내부
주소라 Worker 가 닿지 못하므로 "복사"가 필요했다).

**지금은 정규 경로가 아니다.**

- 화면이 이것을 "실측을 보는 방법"으로 안내하지 않는다.
- 축 1(4종 읽기)이 붙으면 **스크립트와 이 절을 함께 폐기**한다.
- 그때까지는 Trino 가 있는 사람의 **로컬 폴백**으로만 남긴다.

## 유지되는 결정 (초판에서 그대로 살리는 것)

- **`_ops_slo`·`_ops_domain` 은 화면 계약이다.** #78 D-2 가 스키마 변경을 금지했고,
  공급자가 바뀌어도 화면은 안 고친다.
- **`_ops_domain` 은 SLO 를 못 재는 도메인도 행으로 남긴다.** `1 / 6` 이라는 관측 자체가
  콘솔이 팀에 던지는 질문이다 — 공백을 채워서가 아니라 보여줘서 움직인다.
- **합성 폴백(`fixtures/slo_sample.sql`)은 모든 행에 `is_sample=1`.** 실측인 척 조용히
  섞이는 게 최악이라, 화면이 그걸 읽어 배너를 띄운다.
- **초록 위장을 별도로 센다.** Airflow 는 success 인데 실제 데이터가 0건인 실행. SLO 가
  통과로 계산되는 날이라 실패 목록에 안 잡힌다(7/7 실사례). 조회 DB 쪽에도 같은 축이
  `_ops_daily_metric.empty_run_count` 로 있다 — **규약과 화면이 같은 것을 센다.**
- **`모른다 ≠ 0`** (#78 공통 원칙 · F-3). 측정하지 못한 값은 `NULL` 로 두고 화면도
  "미확인"으로 구분한다. 0 으로 그리면 관측 공백이 "이상 없음"으로 위장된다.
  조회 DB 는 이걸 위해 `rows_observed_count`·`rows_unknown_count` 를 나눠 싣고,
  `_ops_pipeline_state.observation_state` 에 `complete`/`partial`/`unverified` 를 둔다.

## 대가

- 조회 DB 는 **파이프라인이 쓰는 시점까지만** 맞다 — 실시간이 아닌 건 초판과 같다.
- 콘솔이 남의 스키마(`d1_ops.py`)에 의존한다. 그쪽이 컬럼을 더하면(추가만 허용, D-3)
  콘솔은 따라 읽기만 하면 되지만, **미러를 만들지 않는다**(만드는 순간 정본이 둘이 된다).
- 로컬에는 4종이 없다(팀 조회 DB 에 있다). 개발용 표본은 `fixtures/` 에 두고 소유를
  주장하지 않는다.

## 재검토 조건

- 축 1 구현 완료 시 — `load_slo.py` 폐기, 이 문서에서 Trino 절 삭제.
- `d1_ops.py` 가 컬럼을 더할 때 — 콘솔은 읽는 쪽만 맞춘다(스키마 미러 금지).
