# 0009 — 운영 기록(조회 DB 4종)을 콘솔이 읽기 전용으로 소비한다

- 상태: **채택** (2026-08)
- 관련: ASK-Seoul#78 §8(조회 DB)·§15(적용 순서 3단계 "대시보드 데이터 연결"),
  ASAC-DAG#647(관문+적재기)·#655(첫 실행 검증)·#658(백필 통로),
  [reference/ops-records-log-patterns.md](../reference/ops-records-log-patterns.md)

## 맥락

팀 규약(#78)이 파이프라인 운영 기록의 형식·값 집합·조회 DB 스키마를 확정했고, ASAC-DAG 의
관문·적재기가 실제 D1 에 표 4종을 만들어 적재를 시작했다(2026-08-02 이후분). 기록은 쌓이는데
**사람이 보는 화면이 없다** — 규약 적용 순서의 3단계(대시보드 데이터 연결)가 비어 있다.

## 결정

1. **콘솔이 `_ops_run_event`·`_ops_daily_metric`·`_ops_pipeline_state`·`_ops_pipeline_expectation`
   을 읽는다. 읽기만 한다.** 쓰는 쪽은 ASAC-DAG 의 관문(C-2)과 점검 적재기(C-3)뿐이다.
2. **스키마 정본은 ASAC-DAG `common/ops/d1_ops.py`** (`ops-d1/v1`)다. 로컬 개발용으로
   같은 DDL 을 [migrations/0002](../../migrations/0002_ops_records.sql)에 **미러**하되,
   컬럼을 더하거나 빼지 않는다 — 정본이 바뀌면 미러를 따라 고친다(ALTER 추가 파일).
3. 화면은 [로그 패턴 카탈로그](../reference/ops-records-log-patterns.md)의 인사이트 중
   **I-1~I-13 을 "실행 기록" 탭**으로 만든다. I-14(저장소↔DB 대조)는 적재기 소관이라
   화면 밖이다.
4. **알림은 만들지 않는다.** 콘솔은 조회 전용이고, 푸시는 DB 기반 Airflow 콜백 소관이다
   (#78 C-8, [0008](0008-deferred-scope.md)).
5. **샘플 규약**: 팀 조회 DB 를 로컬에서 읽을 수 없으므로(0002 로컬 전용) 픽스처로 시드한다.
   정본 스키마에 `is_sample` 컬럼을 더할 수 없으니 **값 규약**으로 표시한다 —
   `_ops_run_event.event_id` 는 `smp_` 접두, 나머지 표는 `updated_at='sample'`.
   화면은 이를 감지해 '샘플' 배지를 띄우고, 실측이 섞이면 배지가 그 사실을 알린다.

## 근거

- **D-5**: 화면이 저장소(R2)를 직접 조회하는 방식은 규약이 이미 기각했다 — 응답 속도가
  파일 목록 요금에 묶인다. 조회 DB 소비가 규약이 설계한 경로다.
- 콘솔은 이미 같은 D1 의 `_ops_slo`(파이프라인)·`_request_log`(서빙)를 소비하는 자리라,
  실행 기록이 여기 붙어야 "만든 쪽 문제인가 파는 쪽 문제인가"가 한 화면에서 갈린다.
- 관측 공백을 드러내는 것이 이 콘솔의 존재 이유다([direction](../direction.md)) —
  `layer IS NULL` 건수와 매트릭스의 빈 칸이 그 다음 숫자다(`1 / 6` 처럼).

## 경계

- `monitored=0`(수동 전용 DAG)은 멈춤 판정에서 제외한다(S-4).
- `observation_state='unverified'` 를 장애로 읽지 않는다 — **미확인 ≠ 정상 ≠ 장애**(C-9).
  화면은 셋을 구분해 보여주기만 한다.
- 기대치 표의 정본은 DAG 선언이다(S-1) — 콘솔에서 기대치를 편집하는 기능을 만들지 않는다.

## 재검토 조건

- 정본 스키마 버전이 오르면(`ops-d1/v2` …) 미러와 화면을 같이 갱신한다.
- 콘솔이 팀 D1 을 직접 읽는 승격([0002](0002-local-only-mentor-gate.md) 개정) 시,
  픽스처·샘플 규약의 필요가 사라지는지 재검토한다.
