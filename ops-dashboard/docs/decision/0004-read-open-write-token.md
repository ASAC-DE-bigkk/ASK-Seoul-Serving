# 0004 — ~~읽기는 열고~~ 쓰기만 공유 토큰으로 잠근다

> 🔴 **2026-08-06 개정 — 읽기도 잠갔다.** 이 문서의 **재검토 조건이 발동했다.**
>
> 원 결정의 전제는 *"로컬 전용이라 노출 반경이 작다"* 였다. 그 전제가 사라졌다 —
> 콘솔이 `ops.ask-seoul.kr` 로 **공개 배포**됐고(0015), 실측으로 **인증 없이 200** 이었다:
>
> ```
> https://ops.ask-seoul.kr/api/summary  → 200 · 운영 D1 실행 기록 98일치 · DAG 49건
> https://ops.ask-seoul.kr/api/keys     → 200 · (지금 0건, #85 이후 고객 이메일 마스킹본 노출)
> ```
>
> 재검토 조건은 *"Cloudflare Access / org OAuth 로 교체"* 였는데 **그걸 지금 못 한다** —
> 계정(`Dy950328@…`) 권한이 없어 Access·WAF·IP 규칙이 전부 403 이다. 그래서
> **할 수 있는 것으로 먼저 막는다: 워커 레벨 토큰 게이트.** 아래 §개정 참조.
>
> 이건 **임시 조치**다. Access 는 여전히 필요하고 그 요청은 별건으로 남긴다.

- 상태: **개정** (2026-08-06) / 원 결정 2026-07
- 관련: [0015](0015-single-production-d1.md)(공개 배포의 계기) · [reference/](../reference/) 의 "Cloudflare Access + RBAC"

## 맥락

원래는 `OPS_TOKEN` 미설정이면 503 으로 화면 전체를 껐다("인증 없는 운영 화면이 실수로
열리는 것보다 낫다"). 그런데 이 콘솔의 쓸모는 팀에 화면을 보여주는 것이고, 로컬 전용이라
노출 반경이 작다.

## 결정

읽기와 쓰기를 **다른 문**으로 나눈다.

| | 토큰 없이 | `OPS_TOKEN` (Bearer) |
|---|---|---|
| 요약·키 목록 조회 | ✅ | ✅ |
| 폐기·복구·쿼터·삭제 | ❌ 401 | ✅ |

- 토큰 미설정이면 쓰기는 **503 으로 닫힌다** — 열리는 게 아니라.
- 이메일은 **응답 단계에서** 마스킹한다(`email_masked`). 화면 마스킹은 마스킹이 아니다 —
  API 응답·개발자도구·curl 에 원문이 남는다.
- 토큰 비교는 timing-safe, 토큰은 sessionStorage 에만(URL 금지), 페이지는 noindex.
- 화면의 `can_write` 는 버튼 노출용이다. 조작해도 뚫리지 않는다 — 실제 차단은 서버의
  `requireWrite` 다. **보안 판단은 서버에서만 한다.**

503 전면 차단의 취지는 버린 게 아니라 **쓰기 쪽으로 옮겼다.**

## 한계 (알고 감수하는 것)

- 공유 토큰이라 **"누가 했나"가 남지 않는다.** 감사 로그도 없다(→ [0008](0008-deferred-scope.md)).
- 읽기를 열었어도 노출해도 되는 화면은 아니다 — SLO·요청 로그·키 사용량은 내부 운영 정보다.

## 개정 (2026-08-06) — 읽기도 같은 토큰으로 잠근다

| | 토큰 미설정 | 토큰 없이/틀림 | `OPS_TOKEN` (Bearer) |
|---|---|---|---|
| **모든 `/api/*` 조회** | **503** | **401** | ✅ |
| 폐기·복구·쿼터·삭제 | 503 | 401 | ✅ |

**두 문을 하나로 합친 게 아니라, 읽기 문에 같은 자물쇠를 단 것이다.** `requireRead` 와
`requireWrite` 는 그대로 별개고, 조치는 여전히 `requireWrite` 를 따로 거친다 — 읽기가
뚫려도 쓰기는 안 뚫린다.

- 🔴 **토큰 미설정이면 읽기도 503 이다(fail-closed).** 배포본은 시크릿을 넣기 전까지
  **아무것도 안 내보낸다.** "열려 있는 채로 잊히는 것"보다 "안 보여서 바로 아는 것"이 낫다.
- **정적 페이지(HTML·JS)는 계속 열려 있다.** `run_worker_first = ["/api/*"]` 라 Assets 가
  먼저 서빙하기 때문이다. **데이터는 한 줄도 안 나간다** — 화면이 잠금 오버레이만 띄운다.
  껍데기까지 막으려면 워커가 자산을 대신 서빙해야 하는데, 얻는 것(콘솔 존재 은닉) 대비
  구조 비용이 커서 하지 않았다.
- `/api/trace` 도 잠근다. 원래는 "`request_id` 는 응답 받은 사람만 아는 난수"라 열어 뒀는데,
  **콘솔 전체를 잠그는 마당에 예외를 둘 이유가 없다.**

### 이 조치가 **해결하지 않는 것**

- **여전히 공유 토큰 하나다.** "누가 했나"는 안 남는다 — [0015 §대가](0015-single-production-d1.md)가
  미룬 숙제 그대로다.
- 토큰을 아는 사람 전부가 운영 데이터를 본다. **사람 단위 접근 제어가 아니다.**
- 그래서 Access(또는 org OAuth) 는 **여전히 필요하다.** 이건 그때까지 창을 닫아 두는 것이다.

## 재검토 조건

- **계정 권한이 확보되면 → Cloudflare Access 로 교체**하고 워커 게이트를 걷는다.
  그때 운영자 감사 로그 결정을 새로 작성한다("누가"가 남는 인증이 생기므로).
- **읽기를 다시 열어야 할 이유가 생기면** → 이 문서를 다시 개정한다. 다만 그때는
  "로컬 전용이라 반경이 작다"는 근거를 **쓸 수 없다** — 공개 호스트에 떠 있다.
