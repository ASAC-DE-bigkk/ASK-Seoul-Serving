# 0013 — 원격 D1 에는 **보기 전용으로만** 붙는다 (경고문을 빗장으로 바꾼다)

- 상태: **채택** (2026-08-05)
- 관련: [0002](0002-local-only-mentor-gate.md)(로컬 전용·팀 D1 쓰기 금지) ·
  [0003](0003-single-shared-local-d1.md)(공유 로컬 D1) · [0009](0009-ops-records-consumption.md)(4종 소비) ·
  [0011](0011-per-env-config.md)(환경별 설정) · [../../../docs/environments.md](../../../docs/environments.md)

## 무엇을 정했나

원격 D1(팀 dev · 운영)에 붙는 경로를 **npm 스크립트로 명시하고, 그 경로에 읽기 전용
빗장을 딸려 보낸다.** 사람이 기억해서 지키던 규칙을 코드로 옮긴다.

| 명령 | 무엇을 보나 | 쓰기 |
|---|---|---|
| `npm run dev` | 로컬 Miniflare (게이트웨이와 공유) | **가능** — 조치는 여기서 한다 |
| `npm run dev:dev-d1` | 팀 dev D1 (`--remote --env dev`) | **잠김** |
| `npm run dev:prod-d1` | 운영 D1 (`--remote --env production`) | **잠김** |
| `npm run d1:local` · `d1:dev` · `d1:prod` | 같은 셋을 SQL 로 | **읽기 문장만 통과** |

## 왜 — 경고문은 실수를 막지 못한다

`wrangler dev --remote` 는 **읽기 전용 모드가 아니다.** 그 상태에서 누른 폐기·삭제 버튼은
그대로 팀 DB 에 적용된다. 불변 경계는 "팀(원격) D1 에 쓰지 않는다"([0002](0002-local-only-mentor-gate.md))인데,
지금까지 그 경계를 지킨 것은 **문서의 경고문 한 줄**이었다:

> ⚠️ `npm run dev:remote` 는 보기 위한 것이고, 그 상태에서 조치 버튼을 누르지 않는다.
> 안전장치를 코드로 넣을지는 미정 — 결정되면 여기에 적는다.
> — environments.md (2026-08-04 시점)

이 문장에는 두 가지 문제가 있었다.

**① 화면이 로컬일 때와 똑같이 생겼다.** 조치 버튼은 같은 자리에 같은 모양으로 있고,
누르는 사람은 자기가 어느 DB 를 보고 있는지를 **그 순간에 기억**해야 했다. 운영 배지가
붉게 떠 있어도, 키 하나를 급히 막으려는 사람의 시야에 그게 들어온다는 보장이 없다.

**② 되돌릴 수 없다.** 이 콘솔의 조치는 폐기·쿼터·**삭제**다. 삭제는 키·사용량·버스트를
연쇄로 지우고 복구 경로가 없다. "한 번 실수하면 배운다"가 성립하지 않는 종류다.

경고문으로 지킬 수 있는 경계였다면 애초에 불변 경계가 아니다.

## 어떻게 — 빗장은 명령에 딸려 온다

`ENV_READONLY=1` 이면 `canWrite()` 가 무조건 `false` 를 돌려주고 `requireWrite()` 가
503 을 낸다. 값은 **`package.json` 의 원격 스크립트가 `--var ENV_READONLY:1` 로 넘긴다.**

핵심은 **사람이 켜는 것이 아니라 경로에 딸려 온다**는 점이다. 원격에 붙는 방법이
`dev:dev-d1`·`dev:prod-d1` 두 개뿐이고 둘 다 빗장을 들고 있으므로, 빗장 없이 원격에
붙으려면 스크립트를 우회해 wrangler 를 직접 쳐야 한다 — 그건 실수가 아니라 **의도**다.

### 빗장을 `wrangler.toml` 에 두지 않은 이유

`[env.production.vars]` 에 `ENV_READONLY = "1"` 을 박는 편이 짧지만, 그러면 **언젠가 그
섹션으로 배포할 때 같이 따라간다.** 배포된 콘솔은 조치가 되어야 하는 물건이라
(그게 존재 이유다) 거기서는 빗장이 틀렸다. 지금 잠가야 하는 것은 *운영 D1* 이 아니라
**"내 노트북에서 운영 D1 에 붙은 상태"** 다 — 그건 환경이 아니라 **실행 방식**이라서
설정이 아니라 명령에 둔다.

### 서버가 잠그고, 화면은 이유를 말한다

- **서버** — `requireWrite()` 가 토큰 검사보다 **먼저** 읽기 전용을 본다. 올바른 토큰을
  들고 와도 막힌다. 응답은 401(인증)이 아니라 **503 + "보기 전용 모드"** 다.
  원인이 토큰이 아니라 대상 DB 라는 것을 응답이 그대로 말해야 한다.
- **화면** — 잠금 해제 버튼이 `보기 전용 · 원격 D1` 로 바뀌고 눌리지 않는다. 환경 배지에도
  `· 보기 전용` 이 붙는다. 버튼을 남겨 두면 토큰을 넣어 보다가 "내 토큰이 틀렸나"로 헤맨다.
- **`meta.env.readonly`** 를 `can_write` 와 **따로** 싣는다. 합치면 화면이
  "토큰이 맞지 않습니다"라는 **거짓말**을 하게 된다 — 원인이 다른 두 상태다.

### SQL 은 화이트리스트로 거른다

`d1-query.mjs` 는 `SELECT`·`WITH`·`PRAGMA`·`EXPLAIN` 으로 **시작하는 한 문장**만 통과시키고,
그 안에 쓰기 낱말이 섞여 있으면(`WITH x AS (...) DELETE ...`) 거절한다. 값을 설정하는
`PRAGMA ... = ...` 도 막는다.

블랙리스트("위험한 낱말을 지운다")를 쓰지 않은 이유는 **빠뜨린 낱말이 곧 사고**이기
때문이다 — `REPLACE INTO`·`VACUUM`·`ATTACH` 는 처음 목록에 없었다.

문자열 리터럴과 주석은 검사 전에 지운다. 안 지우면 `SELECT 'DELETE' AS label` 같은
멀쩡한 조회가 막히고, 반대로 주석 뒤에 숨긴 문장을 놓친다.

## 대가

- **원격에서는 조치를 못 한다.** 팀 dev D1 의 키를 급히 막아야 하면 이 콘솔로는 안 된다 —
  그건 원래 [0002](0002-local-only-mentor-gate.md)가 금지한 일이고, 이제 코드가 그렇게 동작할 뿐이다.
- **환경이 하나 늘었다**(`[env.dev]`). `[env.production]` 과 마찬가지로 상속되지 않으므로
  `assets`·`run_worker_first`·`vars` 를 **세 곳**에서 같이 고쳐야 한다(environments.md §4-①).
- `d1-query.mjs` 의 화이트리스트는 정상 질의를 막을 수 있다. 막히면 화이트리스트를 넓히는
  게 아니라 **그 질의가 정말 읽기인지** 먼저 본다.

## 재검토 조건

- **배포가 승인될 때**([0002](0002-local-only-mentor-gate.md) 개정 + agreement §8) — 배포본은
  빗장 없이 돌아야 한다. `--var` 에만 있으므로 지금 구조에서 자동으로 그렇게 되지만,
  그때 이 문서로 한 번 확인한다.
- **원격에서 조치가 필요해질 때** — 0002 개정이 먼저다. 빗장을 푸는 게 아니라
  "누가 언제 무엇을 했나"가 남는 인증([0004](0004-read-open-write-token.md) 개정)이 선행이다.
- **게이트웨이(marketplace)가 같은 구조를 도입할 때** — 저쪽은 `_burst`·`_usage`·
  `_gateway_request_log` 때문에 **모든 요청이 쓴다.** 같은 빗장으로는 안 되고 계량 경로를
  어떻게 할지가 먼저다 — **그 판단은 게이트웨이 담당자 몫이다.**
