# 0009 — 환경별 설정을 같은 이름·다른 디렉토리로 가른다

- 상태: **채택** (2026-08)
- 관련: [0001](0001-separate-worker-from-marketplace.md)(별도 호스트) ·
  [0002](0002-local-only-mentor-gate.md)(로컬 전용) · [0003](0003-single-shared-local-d1.md)(공유 D1)
- 공동: 게이트웨이(`../../../marketplace`)와 **같은 구조**를 쓴다.
  규약 정본은 [../../../docs/environments.md](../../../docs/environments.md).

## 맥락

배포 형태가 정해졌다 — API 는 `ask-seoul.kr`, 콘솔은 `ops.ask-seoul.kr`, 그리고 D1 이
환경마다 다르다(dev/local `9db0e851-…` · 운영 `59a8409e-…`). 지금까지는 설정이
프로젝트 루트의 `wrangler.toml` 하나였고, 그 안의 값은 로컬 전용이라는 전제로 쓰였다.

전제가 깨진다. 같은 항목(D1·호스트·시크릿)이 환경마다 다른 값을 가져야 한다.

## 결정

**환경별로 디렉토리를 가르고, 파일 이름은 같게 둔다.**

```text
config/local/wrangler.toml   config/local/.dev.vars
config/prod/wrangler.toml
```

명령은 `-c` 로 어느 환경인지만 고른다. `dev` 도 `deploy` 도 **같은 파일을 참조**한다.

**프로젝트 루트의 `wrangler.toml` 은 지운다.**

## 근거

- **환경 차이가 명령줄이 아니라 파일에 남는다.** 명령줄에 흩어져 있으면 문서·스크립트·사람의
  기억 세 곳이 각자 진실을 갖는다. 파일이면 한 곳이다.
- **`-e/--env`(한 파일 안의 섹션) 대신 파일 분리를 고른 이유**는 "무엇이 환경마다 다른가"가
  디렉토리로 바로 보이기 때문이다. 섹션 방식은 상속 규칙을 알아야 읽힌다.
- **루트 설정을 남기지 않는 이유**는 `-c` 를 빠뜨렸을 때다. 남겨 두면 wrangler 가 그걸 조용히
  집어 **틀린 환경으로 돈다.** 지우면 즉시 멈춘다 — 시끄러운 실패가 조용한 오작동보다 낫다.
- 포트도 `[dev] port` 로 파일에 박았다. 기본값에 맡기면 포트가 점유됐을 때 wrangler 가
  조용히 다음 번호로 넘어가 "떴는데 아무도 못 찾는" 상태가 된다(:8789 로 밀린 실사례).

## 대가

`-c` 로 설정 위치를 옮기면 **wrangler 가 그 파일 기준으로 다른 것들도 찾는다.** 셋이 같이
움직이고, 셋 다 조용히 틀린다 — 그래서 전부 명시하거나 옮겼다.

| 따라 움직인 것 | 결과 | 대응 |
|---|---|---|
| `main`·`assets` 상대 경로 | config 기준으로 해석 | `../../` 로 적는다 |
| `.dev.vars` | config 옆에서 찾음 | `config/local/` 로 **옮겼다** |
| 로컬 상태(`.wrangler/state`) | config 옆에 생성 | `--persist-to` 를 항상 명시 |

세 번째가 제일 위험하다 — 상태가 갈리면 게이트웨이와 공유하던 D1 을 잃고
([0003](0003-single-shared-local-d1.md)) 서빙 품질·키 관리 탭이 통째로 빈다.

## 0002(로컬 전용)와의 관계

**`config/prod/wrangler.toml` 이 생겼다고 배포가 허용된 것이 아니다.** 0002 는 그대로다.

- `wrangler deploy` 는 여전히 멘토 게이트(#476 ①)다.
- `package.json` 에 deploy 스크립트를 **여전히 만들지 않는다.**
- 콘솔은 그에 더해 Cloudflare Access 승격(#20 결정 B-1)이 선행이다 — 지금 이대로 올리면
  무인증으로 전체 키 목록이 열린다.

이 파일의 성격은 **"승인이 나면 무엇을 쓰면 되는지"의 실행 가능한 명세**다. 값을 미리 확정해
두는 편이, 승인 시점에 급히 만들다 틀리는 것보다 낫다. `config/prod/wrangler.toml` 머리에
같은 경고를 적어 두었다.

## 하지 않은 것

- **`config/dev/` 를 미리 만들지 않았다.** dev 환경 값이 아직 정해지지 않았고, 값 없는 환경을
  디렉토리로 세우면 그게 실체인 줄 안다. local 이 dev D1 을 가리키고 있어 dev 가 서면
  그 값을 옮기면 된다.
- 설정 생성기·템플릿 엔진을 넣지 않았다. 환경 2개 · 항목 3개다.

## 재검토 조건

- dev 환경이 실제로 서면 `config/dev/` 추가 — 이 결정의 개정이 아니라 적용이다.
- 환경이 늘어 두 파일의 공통부 중복이 부담이 될 때. 그때 `-e/--env` 상속이나 생성기를 본다.
- 콘솔 공개 배포가 승인될 때 — 0002 개정과 함께 이 문서의 "0002와의 관계" 절을 갱신한다.
