# 0009 — 환경별 설정은 한 파일 안의 [env.production] 섹션으로 가른다

- 상태: **채택** (2026-08) — 초안의 `config/<env>/` 파일 분리안을 **철회**하고 개정
- 관련: [0001](0001-separate-worker-from-marketplace.md)(별도 호스트) ·
  [0002](0002-local-only-mentor-gate.md)(로컬 전용) · [0003](0003-single-shared-local-d1.md)(공유 D1)
- 공동: 게이트웨이(`../../../marketplace`)와 **같은 구조**를 쓴다 (#28 이 먼저 채택).
  실행 규약 정본은 [../../../docs/environments.md](../../../docs/environments.md).

## 맥락

배포 형태가 정해졌다 — API 는 기준 도메인, 콘솔은 `ops.` 서브도메인, D1 은
dev(`9db0e851-…`)와 운영(`59a8409e-…`, 8/3 신설)으로 갈린다. 같은 항목(D1·호스트·시크릿)이
환경마다 다른 값을 가져야 한다.

같은 문제에 해법이 두 개 나왔다. #27 초안은 **`config/local`·`config/prod` 파일 분리 + `-c`**,
게이트웨이 #28 은 **한 파일 + `[env.production]` 섹션 + `--env production`**.

## 결정

**#28 방식으로 통일한다.** 프로젝트 루트 `wrangler.toml` 하나 — 기본 환경이 로컬,
`[env.production]` 이 배포. 명령은 배포할 때만 `--env production` 을 명시한다.

## 근거 — 판단 기준은 "누가 실수를 막아주나"

- **파일 분리안은 `-c` 누락이 곧 버그다.** 모든 wrangler 호출(스크립트 포함)에 `-c` 와
  `--persist-to` 를 사람이 매번 붙여야 하고, #27 자신 안에서만 검증 스크립트 3곳이 깨졌다
  (`verify-request-log.mjs` · `usage` · `load_slo.py`). 스크립트를 추가할 때마다 같은 세금을 낸다.
- **섹션 방식은 실수의 방향이 안전한 쪽으로 기운다.** 플래그가 없으면 로컬이고, prod 는
  `--env production` 을 명시해야만 선택된다 — 도구의 기본 동작이라 세금이 없다.
- 파일 분리안이 노린 실익(운영 전용 항목 격리, "이 파일이 있다고 배포 허용 아님" 경고)은
  `[env.production]` 섹션 안에 전부 흡수된다.

## 파일 분리 실험에서 챙겨온 것

철회했지만 그 과정의 산출은 살렸다.

- **포트 고정** — `[dev] port`. 기본값에 맡기면 포트 점유 시 wrangler 가 조용히 다음 번호로
  넘어가 "떴는데 아무도 못 찾는" 상태가 된다(:8789 로 밀린 실사례).
- **prod 섹션 머리의 경고 주석** — 배포 3중 선행(0002 개정 + 멘토 게이트 + Access 승격)과
  "명세이지 승인이 아니다".
- **`.dev.vars` 위치 규약의 실측** — wrangler 는 시크릿 파일을 설정 파일 옆에서 찾는다.
  지금 구조(루트 설정)에선 루트가 맞고, 설정을 옮기면 시크릿도 따라간다는 사실은
  environments.md 에 남겼다.

## 대가

- **env 섹션은 상속되지 않는 항목이 많다.** `[env.production.assets]`·`run_worker_first` 를
  기본 환경과 **중복 명시**해야 하고, 라우트 추가 시 두 곳을 같이 고쳐야 한다 — 한쪽만
  고치면 배포본에서만 깨진다. environments.md §4-① 로 규약화했다.
- `--env production` 누락은 "prod 에 배포할 생각이었는데 로컬/기본으로 감"이 된다 —
  방향이 안전할 뿐 실수 자체는 남는다. 배포가 런북 수동 절차라 걸러진다.

## 재검토 조건

- dev 환경이 실제로 서면 `[env.dev]` 추가 — 이 결정의 적용이지 개정이 아니다.
- 콘솔 공개 배포가 승인될 때 — 0002 개정과 함께 `routes` 활성화·Access 한정 적용을 같이 본다.
