## 왜

**dev D1 이 실질적으로 비어 있었다.** 2026-08-04 실측:

| 표 | dev D1 | 운영 D1 |
|---|---|---|
| `_ops_run_event` | 표 있음 · **0행** | **19,832** |
| `_ops_daily_metric` | 표 있음 · **0행** | 73 |
| `_publication_ledger` | **표 없음** | **4,752** |

파이프라인(ASAC-DAG)은 운영 D1 에만 적재한다. 그래서 dev D1 로는 **실행 기록·발행 점검
탭을 검증할 수 없었고**, 화면을 제대로 보려면 두 환경을 오가야 했다. 검증을 못 하는
환경을 유지하는 비용이, 그 환경이 주는 안전보다 커졌다는 것이 팀 판단이다.

동시에 **환경이 둘이라는 사실 자체가 사고 원인**이었다 — `--env` 를 빠뜨리면 조용히 다른
DB 를 보고, 결과가 그럴듯해서 틀린 줄도 몰랐다(0013 초안이 잡으려던 바로 그 문제).
환경을 하나로 줄이면 그 실수의 자리가 없어진다.

## 무엇이 바뀌나

### 1. 로컬 구동이 곧 운영 접속이다

```
npm run dev   →   wrangler dev (바인딩 remote=true)   →   ask-seoul-prod-d1 (실물)
```

`--persist-to` 로 게이트웨이와 로컬 상태를 공유하던 구조는 **없앴다.** 로컬 Miniflare
사본이 없으므로 [0003](0003-single-shared-local-d1.md)의 "공유 로컬 D1"은 **"공유 운영
D1"** 으로 읽는다 — 원본이 하나라는 취지는 그대로고, 그 하나가 운영으로 옮겨간 것이다.

### 2. 🔴 쓰기 빗장을 걷었다

예전 규약은 **"팀(원격) D1 에 쓰지 않는다"** 였다([0002](0002-local-only-mentor-gate.md)).
그 경계를 **팀이 명시적으로 해제**했다. 로컬 콘솔의 키 조치(폐기·복구·쿼터·삭제)가
**실제 고객 키에 그대로 간다.**

`0013`(원격 보기 전용 빗장)은 이 결정으로 **폐기**한다 — 채택 전에 방향이 바뀌었다.

### 3. dev 배포 폐지 → 운영 배포

| | 전 | 후 |
|---|---|---|
| 콘솔 배포 | `dev-ops.ask-seoul.kr` (`--env dev`) | **`ops.ask-seoul.kr`** (`--env production`) |
| CD 트리거 | `dev` 브랜치 푸시 | **같음** |

⚠️ **브랜치 이름과 배포 환경이 달라졌다.** `dev` 에 머지하면 **운영이 나간다.**

## 대가 — 무엇을 잃는지 알고 택했다

이 결정은 안전장치를 여러 겹 걷어낸다. 나중에 "왜 이렇게 위험하게 해 뒀지"라고 묻지
않도록, 잃은 것을 그대로 적는다.

- 🔴 **연습할 곳이 없다.** 실수의 방향이 더는 안전한 쪽이 아니다. 예전에는 플래그를
  빠뜨리면 로컬로 떨어졌지만, 이제 **기본값이 운영**이다. `npm run dev` 로 띄운 화면의
  '삭제' 두 번 클릭이 실제 고객의 키·이메일·사용량을 지운다(불가역).
- 🔴 **"누가 했나"가 안 남는다.** 쓰기 인증은 여전히 **공유 정적 토큰 하나**(`OPS_TOKEN`)다
  ([0004](0004-read-open-write-token.md)). 원래 §9 는 원격 쓰기 허용의 **선행 조건**으로
  귀속 가능한 인증을 요구했는데, 그 선행 없이 열었다. 조치 이력이 필요해지면 그때는
  이미 지나간 일을 복원할 수 없다.
- 🔴 **로컬 테스트가 운영 지표에 섞인다.** 게이트웨이가 같은 D1 을 쓰게 되면(그쪽 결정
  대기, #85) 로컬 구동만으로 운영 `_gateway_request_log`·`_keys` 에 행이 쌓인다.
  실제로 이 전환 직전의 검증 한 번이 테스트 키 2개와 로그 90여 건을 만들었다 —
  그게 운영에 들어갔을 것이다.
- **오프라인 개발이 불가능하다.** 네트워크와 Cloudflare 자격증명이 없으면 화면이 안 뜬다.
- **읽기 경로가 무인증인 채 운영 호스트에 뜬다.** Access 승격(#20 B-1)이 여전히 미완이다.

**그래서 남긴 최소한**: 데이터 쓰기는 열되 **스키마는 잠근다**(아래 §안전장치).

## 안전장치 — 유일하게 남긴 경계

**"쓰지 마라"는 걷었지만 "남의 표 모양을 바꾸지 마라"는 그대로다.** 둘은 다른 약속이고,
후자는 이 결정과 무관하게 살아 있다([CLAUDE.md](../../CLAUDE.md) §6 소유권).

| 표 | 정본 | 콘솔 권한 |
|---|---|---|
| `_ops_slo`·`_ops_domain` | **여기** | 스키마·내용 모두 |
| `_keys`·`_usage`·`_burst`·`_gateway_request_log` | `../marketplace/migrations/` | 데이터 조치만 — **스키마 불변** |
| `_ops_run_event` 외 3종 | ASAC-DAG | 읽기 — **스키마 불변** |
| `_catalog`·`_publication_ledger` | 도메인 export(dbt) | 읽기 — **스키마 불변** |

- DDL(`CREATE`·`ALTER`·`DROP` …)은 `scripts/d1-query.mjs` 가 **전부 막는다.** 대상 표가
  무엇이든 스키마는 마이그레이션 장부를 거쳐야 한다([0007](0007-schema-single-file-reset.md)).
- 남의 표에 데이터를 쓰면 **경고를 찍는다.** 막지는 않는다 — 키 조치가 그 경로다.
- `migrations/` 는 전부 `CREATE TABLE IF NOT EXISTS` 이고 DROP·ALTER 가 없다. 운영에
  적용해도 **있는 표는 건드리지 않는다.**

## 재검토 조건

- **조치 이력이 필요해지면** → [0004](0004-read-open-write-token.md) 개정으로 귀속 가능한
  인증을 먼저 세운다. 지금 구조로는 "누가 지웠나"에 답할 수 없다
- **로컬 테스트가 운영 지표를 실제로 오염시키면** → 쓰기 경로에 표시를 남겨 집계에서
  거르는 축을 만든다(#78 Z-7 이 환경 스코프로 같은 문제를 이미 푼 적 있다)
- **Access 가 확보되면** → `ops.ask-seoul.kr` 을 그 뒤로 넣는다(#20 B-1)
- **다시 격리 환경이 필요해지면** → 이 문서를 개정한다. dev D1 을 되살리는 것이 아니라
  **왜 필요해졌는지**부터 적는다 — 없앤 이유가 "검증이 안 되는 빈 DB" 였기 때문이다
