API 문서

읽기 전용 REST API 입니다. 응답은 JSON, 오류는 RFC 7807 형식을 따릅니다. 규격은 OpenAPI 3.1 문서로도 제공되어 Postman·Swagger 등에 그대로 가져다 쓰실 수 있습니다.

기본 규격 인증 엔드포인트 필터와 정렬 페이지네이션 응답 헤더 오류 코드 코드 예제 크로스도메인 조인 변경 이력

기본 규격 Basics

프로토콜HTTPS 읽기 전용입니다. 데이터 조회는 GET 만 받습니다(키 발급·폐기만 POST·DELETE).
응답 형식JSON application/json; charset=utf-8. 오류는 application/problem+json.
CORS허용 모든 출처에서 호출할 수 있습니다(Access-Control-Allow-Origin: *). 브라우저에서 직접 부르셔도 됩니다.
문자 인코딩UTF-8 한글 값이 그대로 들어 있습니다. 테이블·컬럼 이름은 영문 소문자와 밑줄만 씁니다.
시간 기준KST 데이터의 날짜 축과 일일 한도 초기화는 한국 시간 기준입니다. 발행 시각(exported_at)만 ISO 8601 UTC 입니다.
본격적으로 연결하시기 전에 브라우저에서 한 번 불러 보세요. 플레이그라운드에서 데이터·기간·행 수를 고르면 호출할 주소가 완성되고, 응답을 표와 JSON 원문으로 바로 확인하실 수 있습니다. 키로 인증해 보내는 실제 호출이라 일일 한도에서 차감됩니다. 아래 문서는 그 주소를 코드에서 직접 만드는 방법입니다.

인증 Authentication

데이터 조회에는 API 키가 필요합니다. Authorization 헤더에 Bearer 토큰으로 넣습니다.

Authorization: Bearer ask_0123456789abcdef0123456789abcdef

키는 ask_ 로 시작하는 32자리 16진수입니다. 카탈로그의 인증 영역에서 Google 계정으로 로그인하면 즉시 발급되며, 비밀번호나 결제수단은 받지 않습니다. 이메일 소유는 Google 이 확인해 줍니다.

키는 발급 시점에 한 번만 표시됩니다. 서버에는 SHA-256 해시와 표시용 앞 8자만 저장하므로 저희도 원문을 복원할 수 없습니다. 잃어버리셨다면 기존 키를 폐기한 뒤 다시 로그인하시면 새 키를 받습니다 — 같은 계정으로 다시 로그인하는 것만으로는 기존 키를 만료시키지 않습니다(말없이 무효화하지 않기 위해서입니다).

키 없이 되는 것 — 제품 목록(/api/v1/catalog)과 샘플 5행 미리보기(/api/v1/preview/…)는 인증 없이 부르실 수 있습니다. 쓸만한지 먼저 확인하고 키를 받으시라는 뜻입니다.

이메일만 적어 발급하던 옛 경로(POST /api/v1/keys)는 폐지됐습니다. 호출하면 403 과 함께 응답의 auth_url 이 열려 있는 발급 경로를 알려 줍니다.

엔드포인트 Endpoints

GET/api/v1/catalog인증 불필요

공개 중인 전 제품의 메타데이터를 한 번에 돌려줍니다. 스키마·행 수·시간축·발행 시각·조인 축이 들어 있어, 클라이언트가 카탈로그를 캐시해 두고 쓰기에 적합합니다.

{
  "attribution": "공공 원천의 2차 가공물 — 출처·이용조건 /attribution",
  "docs": "/llms.txt",
  "join_axes": ["admin_dong_code", "gu_code", "stat_region_cd"],
  "products": [
    {
      "name": "gold_culture_event_schedule",   ← 물리 테이블명(과도기 별칭으로도 받는다)
      "product_id": "culture_event_schedule",  ← /api/v1/data 에 넣는 값
      "description": "문화행사 목록 질의 표면(행사 1행) …",
      "time_axis": "event_start_date",          ← from/to 가 걸리는 컬럼. null 이면 기간 필터 불가
      "columns": [{ "name": "gu_code", "type": "TEXT" }],
      "row_count": 38104,
      "join_keys": ["gu_code"],                 ← 이 제품이 가진 공통 축
      "exported_at": "2026-07-31T03:14:22.000Z"   ← 커서 유효성의 기준
    }
  ]
}
GET/api/v1/preview/{product_id}인증 불필요 · 무과금

고정 5행 샘플입니다. 필터를 받지 않고, 일일 한도를 소모하지 않습니다. 시간축이 있는 제품은 최신 구간을 보여줍니다. 분당 한도는 IP 기준으로 적용됩니다.

GET/api/v1/data/{product_id}인증 필요

본 조회입니다. 필터·기간·페이지네이션을 지원합니다.

{
  "table": "gold_culture_event_schedule",
  "row_count": 500,
  "limit": 500,
  "time_axis": "event_start_date",
  "has_more": true,
  "next_cursor": "NTAwQDIwMjYtMDctMzFUMDM6MTQ6MjIuMDAwWg",
  "usage": { "used": 3, "daily_quota": 1000 },
  "rows": [ … ]
}
GET/api/v1/me인증 필요

내 키의 오늘 사용량을 확인합니다. { key_prefix, email, day, used_today, daily_quota } 를 돌려줍니다.

GET/api/v1/auth/google인증 불필요

브라우저로 여는 주소입니다. Google 로 로그인하면 이메일 소유를 Google 이 확인해 주고, 확인된 주소로 키가 발급됩니다. 키는 그 화면에 한 번만 표시됩니다. 이메일 1개에 키 1개이며, 이미 키가 있으면 기존 키 앞자리를 알려 드립니다(재발급하지 않습니다).

DELETE/api/v1/keys인증 필요

키를 폐기합니다. ?purge=true 를 붙이면 이메일과 사용량 기록까지 삭제합니다. 이미 폐기한 키로도 삭제를 요청하실 수 있습니다 — 폐기가 “지울 권리”의 문을 닫아서는 안 되기 때문입니다.

GET/api/v1/products/{product_id}인증 필요 · 무과금

제품 하나의 메타를 한 번에 돌려줍니다 — 컬럼 설명·grain·기본키·시간축·출처·신선도, 그리고 검증된 질의 패턴(usage_patterns)까지 들어 있습니다. /api/v1/catalog 가 전 제품의 얕은 목록이라면 이쪽은 한 제품의 깊은 설명입니다. 조회 전에 한 번 부르면 필터에 쓸 컬럼을 확인할 수 있습니다.

GET/api/v1/glossary인증 필요 · 무과금

코드값의 뜻을 돌려줍니다(예: 요일 코드, 혼잡도 등급). ?vocabulary_id= 로 좁힐 수 있습니다. 제품 응답에 숫자·약어로 들어오는 값의 의미를 여기서 찾습니다.

POST/mcp도구 호출부터 인증

MCP(Model Context Protocol) 서버입니다. Streamable HTTP · JSON-RPC 2.0 단일 엔드포인트로, Claude·Cursor 같은 MCP 클라이언트에 등록하면 에이전트가 스스로 제품을 찾아 질의합니다. 도구는 list_products · describe_product · preview_product · query_product · run_pattern · check_quota 여섯 개이고, REST 와 같은 키·같은 한도를 씁니다. 연결 방법과 도구별 설명은 가이드에 있습니다.

initialize · tools/list 는 인증 없이 되고, 데이터를 만지는 tools/call 부터 키가 필요합니다. 도구 실패는 HTTP 200 봉투 안의 isError: true 로 옵니다 — 내용을 읽고 그대로 따르시면 됩니다.

필터와 정렬 Query

limit정수 한 번에 받을 행 수. 기본 500, 최대 5,000. 넘겨 보내면 5,000으로 잘립니다.
from날짜 시간축 이상. 제품에 time_axis 가 없으면 400 no time axis 입니다.
to날짜 시간축 이하. from 과 함께 기간을 만듭니다.
cursor문자열 이전 응답의 next_cursor 를 그대로 넣습니다. 아래 페이지네이션 참고.
<컬럼명>일치 그 밖의 모든 쿼리 파라미터는 컬럼 일치 필터로 해석됩니다. 예: ?gu_code=11110. 없는 컬럼을 주면 400 unknown filter 와 함께 사용 가능한 컬럼 목록을 돌려드립니다.
GET /api/v1/data/culture_event_schedule?gu_code=11110&from=2026-08-01&to=2026-08-31&limit=100
기간 필터는 시작일 하나만 봅니다. 행사처럼 기간을 갖는 데이터에서 from/to 는 제품의 time_axis 컬럼 한 개에만 걸립니다. “이번 주말에 진행 중인 행사”처럼 기간이 겹치는 것을 찾으시려면 종료일 컬럼(예: event_end_date)을 받아서 클라이언트에서 함께 판단하셔야 합니다.

정렬은 지정할 수 없습니다. 응답은 항상 내부 저장 순서(rowid)로 고정되어 있으며, 이것이 커서 페이지네이션이 행을 빠뜨리지 않는 근거입니다. 원하는 순서는 받으신 뒤 정렬하세요.

페이지네이션 Pagination

offset 방식이 아니라 커서 방식입니다. 성능이 아니라 정확성 때문입니다 — 제품은 발행 때마다 통째로 다시 쓰이고(도메인에 따라 매시간~매일), 그 사이 offset 은 같은 행을 두 번 주거나 건너뜁니다.

응답의 has_more 가 true 면 next_cursor 를 그대로 다음 요청에 넣습니다. false 면 마지막 페이지이고 next_cursor 는 null 입니다.

# 1페이지
GET /api/v1/data/culture_event_schedule?limit=1000
→ has_more: true, next_cursor: "NTAwQDIwMjYt…"

# 2페이지 — 다른 파라미터는 그대로 두고 cursor 만 추가
GET /api/v1/data/culture_event_schedule?limit=1000&cursor=NTAwQDIwMjYt…
409 cursor expired 를 반드시 처리하세요. 페이지를 넘기는 중에 그 제품이 새로 발행되면 이전 커서는 다른 발행의 위치를 가리킵니다. 그대로 이어받으면 행이 조용히 빠지므로, 저희는 그걸 감추지 않고 409 로 알립니다. 받으시면 첫 페이지부터 다시 받으시면 됩니다. 큰 제품을 통째로 받는 작업은 그 제품의 발행 시각을 피해 돌리시는 편이 안전합니다 — 마지막 발행 시각은 카탈로그의 exported_at 으로 확인하실 수 있습니다.

페이지마다 일일 한도를 1회 소모합니다. limit 을 키우면 호출 수를 줄일 수 있습니다.

응답 헤더 Headers

X-Request-Id전 응답 req_ 로 시작하는 이 요청의 식별자. 오류 응답에는 본문의 request_id 로도 들어갑니다. 문의하실 때 이 값을 알려주시면 해당 요청을 바로 찾을 수 있습니다.
X-RateLimit-Limit인증 응답 일일 한도(기본 1,000).
X-RateLimit-Remaining인증 응답 오늘 남은 호출 수. 직접 세지 마시고 이 값으로 속도를 조절하세요.
X-RateLimit-Reset인증 응답 한도가 초기화되는 시각(Unix epoch 초). 한국 시간 자정입니다.
Retry-After429 일부 분당 한도 초과 시에만 내려갑니다. 이 초만큼 기다렸다가 재시도하세요.

오류 코드 Errors

오류는 RFC 7807 application/problem+json 형식입니다. status 로 분기하지 마시고 title 로 분기하세요 — 같은 상태 코드에 원인이 여럿입니다.

상태title원인과 대처
400unknown filter없는 컬럼으로 필터했습니다. 응답 detail 에 사용 가능한 컬럼 목록이 들어 있습니다.
400no time axis시간축이 없는 제품에 from/to 를 줬습니다. 기간을 빼고 부르세요.
400invalid cursor커서를 가공했거나 잘못 옮겼습니다. next_cursor 를 그대로 넣어야 합니다.

401unknown api key등록되지 않은 키입니다. 오타이거나 삭제된 키입니다.
403email issuance disabled폐지된 이메일 발급 경로를 부르셨습니다. 응답의 auth_url 이 열려 있는 경로를 알려 줍니다.

실패한 요청은 일일 한도를 소모하지 않습니다. 한도는 실제로 데이터를 서빙하기 직전에만 셉니다 — 400·404·409 로 끝난 요청은 무과금입니다. 오타를 고쳐가며 붙이시는 동안 한도가 닳지 않습니다.

코드 예제 Examples

커서를 끝까지 따라가며 한 제품을 통째로 받는 예제입니다. 409 처리까지 포함했습니다.

# 1. 키 발급 — 어느 방식이 열려 있는지 먼저 확인
curl "$HOST/api/v1/catalog" | grep -o '"key_issuance":{[^}]*}'

#   google_oauth 라면 → 브라우저로 $HOST/api/v1/auth/google 를 연다 (curl 로는 안 된다)
#   email 이라면 →
curl -X POST "$HOST/api/v1/keys" \
  -H "content-type: application/json" \
  -d '{"email":"you@example.com"}'

# 2. 제품 목록 (키 없이)
curl "$HOST/api/v1/catalog"

# 3. 조회 — 종로구의 8월 문화행사
curl -H "Authorization: Bearer $KEY" \
  "$HOST/api/v1/data/culture_event_schedule?gu_code=11110&from=2026-08-01&to=2026-08-31"

# 4. 남은 한도 확인 (헤더만)
curl -sI -H "Authorization: Bearer $KEY" "$HOST/api/v1/me" | grep -i ratelimit
import requests

HOST = "https://<호스트>"
KEY  = "ask_…"

def fetch_all(table, **filters):
    """커서를 끝까지 따라가 전 행을 모은다. 409 는 재발행 신호라 처음부터 다시 받는다."""
    rows, cursor, attempts = [], None, 0
    while True:
        params = {"limit": 5000, **filters}
        if cursor:
            params["cursor"] = cursor
        r = requests.get(f"{HOST}/api/v1/data/{table}", params=params,
                         headers={"Authorization": f"Bearer {KEY}"}, timeout=30)

        if r.status_code == 409:            # 재발행 — 커서를 버리고 처음부터
            attempts += 1
            if attempts > 2:
                raise RuntimeError("재발행이 반복됩니다 — 발행 시각을 피해 다시 시도하세요")
            rows, cursor = [], None
            continue
        if r.status_code == 429:            # 분당 한도면 Retry-After 만큼 쉰다
            time.sleep(int(r.headers.get("retry-after", 60)))
            continue
        r.raise_for_status()

        body = r.json()
        rows += body["rows"]
        if not body["has_more"]:
            return rows
        cursor = body["next_cursor"]

events = fetch_all("culture_event_schedule", gu_code="11110")
print(len(events), "행")
const HOST = "https://<호스트>";
const KEY  = "ask_…";

async function fetchAll(table, filters = {}) {
  let rows = [], cursor = null, restarts = 0;
  while (true) {
    const q = new URLSearchParams({ limit: "5000", ...filters });
    if (cursor) q.set("cursor", cursor);
    const res = await fetch(`${HOST}/api/v1/data/${table}?${q}`, {
      headers: { authorization: `Bearer ${KEY}` },
    });

    if (res.status === 409) {          // 재발행 — 처음부터 다시
      if (++restarts > 2) throw new Error("재발행이 반복됩니다");
      rows = []; cursor = null; continue;
    }
    if (res.status === 429) {          // 분당 한도 — Retry-After 만큼 대기
      const wait = Number(res.headers.get("retry-after") || 60);
      await new Promise((r) => setTimeout(r, wait * 1000));
      continue;
    }
    if (!res.ok) throw new Error(`${res.status} ${(await res.json()).title}`);

    const body = await res.json();
    rows.push(...body.rows);
    if (!body.has_more) return rows;
    cursor = body.next_cursor;
  }
}

const events = await fetchAll("culture_event_schedule", { gu_code: "11110" });
console.log(events.length, "행");

크로스도메인 조인 Cross-domain

도메인이 다른 두 제품을 같은 축으로 붙일 수 있습니다. 코드 체계를 맞추는 작업이 이미 끝나 있어, 받으신 뒤 컬럼 값을 그대로 대응시키면 됩니다.

admin_dong_codeTEXT 행정안전부 10자리 행정동 코드. 가장 좁은 공통 축입니다.

stat_region_cdTEXT 통계 집계 구역 코드.

어떤 제품이 어떤 축을 갖는지는 /api/v1/catalog 응답의 join_keys 로 내려갑니다. 두 제품 모두에 같은 축이 있으면 조인 가능합니다.
