개인정보 관련 요청

키 폐기와 이메일·사용량 삭제는 문의 없이 직접 하실 수 있고, 그게 가장 빠릅니다. 공개된 곳에 개인정보를 적지 않으셔도 되도록 셀프 경로를 먼저 만들어 두었습니다.

직접 처리하기
공개 저장소입니다. 이슈에 API 키 원문, 이메일 주소, 그 밖의 개인정보를 적지 말아 주세요. 요청을 특정할 때는 아래의 request_id 만으로 충분합니다.

오류를 신고하실 때 Bug report

아래 세 가지가 있으면 저희가 그 요청 하나를 로그에서 바로 집어낼 수 있습니다. 없으면 “언제쯤 무엇을 부르셨는지”부터 되짚어야 해서 확인이 훨씬 늦어집니다.

request_id필수 오류 응답 본문의 request_id 값, 또는 응답 헤더 X-Request-Id. req_ 로 시작하는 문자열입니다.
호출한 주소필수 쿼리 문자열까지 포함한 전체 경로. 키는 빼고 보내주세요.
받은 응답권장 HTTP 상태 코드와 응답 본문. 기대하신 결과와 실제 결과를 함께 적어주시면 가장 좋습니다.

오류 응답은 이런 형태이고, 여기 request_id 가 들어 있습니다.

{
  "type": "about:blank",
  "title": "unknown filter",
  "status": 400,
  "detail": "'gu_name' 컬럼 없음 — 사용 가능: gu_code, ...",
  "request_id": "req_8f2a1c9e4b7d3a06"   ← 이 값을 알려주세요
}

응답에 대해 Response

정직하게 적어 둡니다. 이 서비스는 학습·연구 목적으로 운영하는 프로젝트이고, 상시 대기하는 지원 인력이 없습니다. 문의에 언제까지 답하겠다는 약속을 드릴 수 없습니다.

다만 아래는 지키려 합니다.

  • 데이터가 틀렸다는 제보는 가장 먼저 봅니다. 잘못된 값을 계속 내보내는 것이 이 서비스가 할 수 있는 가장 나쁜 일이라고 보기 때문입니다.
  • 서비스가 멈췄다는 제보가 그다음입니다.
  • 새 데이터 요청과 기능 제안은 받아 두고, 우선순위에 맞춰 처리합니다. 바로 반영된다고 약속드리기는 어렵습니다.

급하게 판단이 필요하시면 서비스 상태에서 지금 API 가 살아 있는지, 데이터가 언제 발행됐는지를 문의 없이 바로 확인하실 수 있습니다.
