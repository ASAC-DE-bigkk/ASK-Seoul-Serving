이용 가이드

흩어져 있는 서울 공공데이터를 같은 축 위에 올려, 코드 몇 줄로 불러 쓸 수 있게 만든 API 입니다. 이 문서는 무엇을 제공하고 무엇을 보장하지 않는지, 어떻게 시작하는지를 담고 있습니다.

무엇을 제공하나 어떻게 만들어지나 시작하기 한도와 갱신 여러 도메인 함께 쓰기 AI 에이전트로 쓰기 자주 묻는 질문

무엇을 제공하나 What

서울시와 공공기관이 각각 다른 형식으로 내놓는 데이터를 수집·정제해, 행정동 코드라는 공통 축 위에 올려 놓은 데이터 제품을 REST API 로 제공합니다. 문화·행사, 인구·도시, 상권, 대중교통, 도로 소통, 날씨 여섯 도메인입니다.

원천 API 를 그대로 중계하지 않습니다. 집계·조인·파생 지표 계산을 거친 2차 가공물이며, 그래서 여러 기관의 데이터를 같은 기준으로 나란히 놓고 볼 수 있습니다. 대신 수치가 원천 제공기관의 공식 발표와 다를 수 있고, 그 차이의 책임은 저희에게 있습니다.

제품 단위로 정제

원본 테이블이 아니라 “답하고 싶은 질문” 단위로 묶어 두었습니다. 카탈로그에서 활용 예시를 함께 보실 수 있습니다.

같은 축으로 조인

도메인이 달라도 행정동 코드가 같으면 그대로 붙습니다. 축을 맞추는 작업이 이미 끝나 있습니다.

키 없이 먼저 확인

모든 제품은 가입 없이 샘플 5행을 미리 볼 수 있습니다. 쓸만한지 보고 나서 키를 받으세요.

어떻게 만들어지나 Pipeline

정해진 시각에 아래 세 단계가 자동으로 돕니다 — 도메인에 따라 매시간 또는 매일입니다. 사람이 손으로 올리는 데이터는 없습니다.

1 · Collect

원천 수집

서울시·기상청·행정안전부 등의 공개 API 에서 원본을 받아 그대로 보관합니다.

2 · Transform

정제와 검증

중복 제거, 행정동 코드 정규화, 파생 지표 계산을 거치고 품질 검사를 통과한 것만 다음 단계로 갑니다.

3 · Publish

서빙 발행

검사를 통과한 제품만 API 저장소로 발행됩니다. 발행 시각은 카탈로그와 상태 페이지에 표시됩니다.

품질 검사에 걸리면 발행하지 않습니다. 이상한 데이터를 내보내느니 어제 것을 그대로 두는 편이 낫다고 보기 때문입니다. 그래서 갱신이 하루 밀릴 수 있고, 각 제품의 마지막 발행 시각은 서비스 상태에서 확인하실 수 있습니다.

시작하기 Quick start

1

쓸 데이터 고르기

카탈로그에서 검색하고, 키 없이 샘플 5행을 미리 봅니다.

2

API 키 받기

Google 계정으로 로그인하면 즉시 발급됩니다. 별도 가입도, 비밀번호도, 결제수단도 없습니다 — 주소가 본인 것인지 Google 이 확인해 주는 방식이라 인증 메일을 기다리실 필요도 없습니다.

3

호출하기

표준 REST 입니다. 아래 한 줄이면 첫 응답을 받습니다.

curl -H "Authorization: Bearer <API_KEY>" \
  "https://<호스트>/api/v1/data/culture_event_schedule?limit=10"

주소에 들어가는 이름은 제품 id(culture_event_schedule)입니다 — 카탈로그에 표시된 값을 그대로 쓰시면 됩니다. 저장소 안의 테이블 이름은 저희 사정이라 바뀔 수 있고, 제품 id 는 바뀌지 않습니다.

파라미터·오류 코드·페이지네이션을 포함한 전체 규격은 API 문서에 있습니다. 브라우저에서 바로 실행해 보시려면 플레이그라운드를 쓰세요.

한도와 갱신 Limits

항목값비고
요금무료결제수단을 받지 않습니다.
일일 한도키당 1,000회한국 시간 자정에 초기화됩니다.
분당 한도60회가용성 보호용입니다. 초과하면 429 와 함께 재시도 시각을 알려드립니다.
미리보기무과금키 없이 쓰는 샘플 5행은 일일 한도를 소모하지 않습니다.
한 번에 받는 행최대 5,000행그 이상은 커서로 이어받습니다.
갱신 주기매시간 ~ 매일도메인마다 다릅니다 — 인구·도시와 대중교통, 도로 소통은 매시간, 문화·행사는 매일 1회입니다. 제품별 마지막 발행 시각은 상태 페이지에 있습니다.
키 발급IP당 시간당 5회이메일 1개에 키 1개입니다.

남은 한도는 매 응답의 X-RateLimit-Remaining 헤더로도 내려갑니다. 직접 세지 않고 이 값을 보고 속도를 조절하시면 됩니다.

여러 도메인 함께 쓰기 Cross-domain

이 서비스의 핵심입니다. 도메인이 달라도 아래 컬럼이 있으면 그대로 조인됩니다 — 코드 체계를 맞추는 작업이 이미 끝나 있습니다.

admin_dong_code행정동 행정안전부 10자리 행정동 코드. 가장 좁은 공통 축입니다.
gu_code자치구 자치구 단위로 묶어 볼 때 씁니다.
stat_region_cd통계구역 통계 집계 구역 기준 데이터끼리 붙일 때 씁니다.

예를 들어 “행사가 있는 날 그 동네가 평소보다 얼마나 더 붐볐나”는 문화·행사 제품과 인구·도시 제품을 admin_dong_code 와 날짜로 붙이면 나옵니다. 각 제품이 어떤 축을 가졌는지는 카탈로그의 스키마에 JOIN 표시로 나와 있고, API 응답에서는 join_keys 필드로 내려갑니다.

AI 에이전트로 쓰기 MCP

REST 말고 MCP(Model Context Protocol) 로도 같은 데이터를 씁니다. Claude·Cursor 같은 MCP 클라이언트에 서버 주소를 등록하면, 에이전트가 어떤 제품이 있는지 스스로 찾아보고 필요한 것만 골라 질의합니다. 사람이 카탈로그를 뒤져 컬럼 이름을 찾아 주지 않아도 됩니다.

# MCP 클라이언트 설정 (Streamable HTTP)
  "url": "https://<호스트>/mcp"
  "headers": { "Authorization": "Bearer <API_KEY>" }

키는 사람이 받아 설정에 넣어 주셔야 합니다 — 에이전트는 브라우저를 열 수 없어 스스로 로그인하지 못합니다. REST 와 같은 키·같은 한도를 씁니다.

도구하는 일쿼터
list_products제품 목록 — 대표 질문·조인키·설명. 어느 제품이 맞는지 고를 때 먼저 부릅니다.무과금
describe_product제품 상세 — 컬럼 설명·시간축·검증된 질의 패턴·출처.무과금
preview_product5행 미리보기 — 필터에 넣을 값의 실제 예시를 봅니다.무과금
query_product데이터 조회 — 등가 필터·기간·커서.1회
run_pattern검증된 질의 패턴 실행(권장) — 도메인 담당자가 미리 검증해 둔 질의를 그대로 돌립니다.1회
check_quota남은 일일 쿼터 확인.무과금

run_pattern 을 권합니다. 에이전트가 필터를 스스로 조립하면 틀린 질의를 만들 수 있는데, 이 도구는 검증을 마친 질의만 돌리므로 답이 어긋날 여지가 적습니다. 쓸 수 있는 패턴은 describe_product 응답에 들어 있습니다.

기계가 읽는 요약은 /llms.txt, 전체 규격은 /openapi.json 에 있습니다.

자주 묻는 질문 FAQ

정말 무료인가요? 나중에 과금되나요?

무료이고, 결제수단을 아예 받지 않습니다. 학습·연구 목적으로 만든 프로젝트라 유료 전환 계획도 없습니다. 다만 그렇기 때문에 가용성을 약속드리지 못합니다 — 아래 항목을 봐주세요.

실시간 데이터인가요?

아닙니다. 원천이 실시간이더라도(예: 실시간 인구, 도로 소통) 이 API 가 내보내는 것은 발행 시점의 스냅샷입니다. 다만 발행 주기는 도메인마다 다릅니다 — 실시간성이 중요한 쪽은 매시간 발행합니다.

초 단위의 지금 값이 필요하시면 원천 API 를 직접 쓰시는 편이 맞습니다. 이 API 는 같은 축으로 붙여 놓은 이력이 필요할 때 쓰는 쪽에 가깝습니다.

제품마다 마지막 발행이 언제였는지는 서비스 상태와 카탈로그에서 확인하실 수 있고, 응답의 exported_at 으로도 확인하실 수 있습니다.

수치가 서울시 공식 발표와 다릅니다.

이 API 의 데이터는 원천을 집계·조인·가공한 2차 산출물이라 원천의 공식 수치와 다를 수 있습니다. 공식 수치가 필요한 용도라면 제공기관의 원천을 인용하셔야 합니다.

가공 과정에서 생긴 차이의 책임은 저희에게 있습니다. 이상해 보이는 값을 발견하시면 문의로 알려주시면 확인하겠습니다.

상업적으로 이용해도 되나요?

저희가 허락하거나 제한할 수 있는 부분이 아닙니다. 각 원천 데이터 제공기관의 이용조건이 우선하며, 기관마다 공공누리 유형과 상업적 이용 가능 여부가 다릅니다. 원천별 제공기관과 조건은 데이터 출처에 표로 정리해 두었습니다.

인용하실 때는 원천 제공기관과 이 서비스를 함께 표시해 주세요. 가공이 들어갔기 때문에 원천만 표시하면 그 기관의 공식 수치로 오인될 수 있습니다.

키를 잃어버렸습니다.

키 원문은 저희도 복원할 수 없습니다. 발급 시점에 한 번만 표시되고, 서버에는 해시(SHA-256)와 표시용 앞 8자만 저장하기 때문입니다.

같은 계정으로 다시 로그인하시면 이미 키가 있다고 안내해 드립니다 — 기존 키를 말없이 만료시키지 않기 위해서입니다. 새 키가 필요하시면 기존 키를 먼저 폐기한 뒤 다시 로그인하세요. 폐기 방법은 아래 항목에 있습니다.

운영 중인 코드가 있다면 폐기 즉시 그 키가 무효가 되므로, 교체할 준비를 하고 진행하세요.

키와 제 이메일을 지우고 싶습니다.

직접 하실 수 있습니다. 카탈로그 상단의 인증 영역에서 키 폐기를 누르면 키가 즉시 무효가 되고, 이어서 이메일·기록까지 삭제를 누르면 이메일과 사용량 기록이 지워집니다. 문의를 기다리실 필요가 없습니다.

자세한 보관 항목과 기간은 개인정보 처리방침에 있습니다.

429 오류가 납니다.

두 가지 경우가 있고, 응답의 title 로 구분하실 수 있습니다.

  • burst rate limited — 분당 60회를 넘었습니다. Retry-After 헤더의 초만큼 기다렸다가 다시 부르세요.
  • daily quota exceeded — 일일 1,000회를 다 쓰셨습니다. 한국 시간 자정에 초기화됩니다.

반복해서 겪으신다면 limit 을 키워 한 번에 더 많이 받는 편이 호출 수를 줄입니다(최대 5,000행).

“커서가 만료됐다”(409)고 나옵니다.

페이지를 넘기는 중에 그 제품이 새로 발행된 경우입니다. 발행이 바뀌면 이전 커서로 이어받을 때 행이 조용히 빠지거나 겹칠 수 있어, 그걸 감추지 않고 오류로 알려드립니다.

커서를 버리고 첫 페이지부터 다시 받으시면 됩니다. 큰 제품을 통째로 받는 작업이라면 발행 시각(새벽)을 피해 돌리시는 편이 안전합니다.

어떤 제품이 있는지 기계가 읽을 수 있는 형식으로 받고 싶습니다.

세 가지 경로가 있습니다.

  • GET /api/v1/catalog — 전 제품의 스키마·행 수·발행 시각·조인 축
  • /openapi.json — OpenAPI 3.1 규격. Postman·Swagger 등에 그대로 가져다 쓰실 수 있습니다.
  • /llms.txt — AI 에이전트용 요약. 사람이 읽어도 짧습니다.
서비스가 갑자기 멈추거나 없어질 수 있나요?

그럴 수 있습니다. 정직하게 말씀드리면 이 서비스는 학습·연구 목적의 프로젝트이고, 가용성이나 지속성을 약속드릴 수 있는 단계가 아닙니다.

업무에 필수적인 용도라면 응답을 자체적으로 보관해 두시거나 원천 API 를 함께 붙여 두시길 권합니다.

문의는 어디로 하나요?

문의 페이지에 창구와, 문의하실 때 함께 알려주시면 좋은 정보를 정리해 두었습니다. 오류를 겪으셨다면 응답의 request_id 를 같이 보내주시면 그 요청 하나를 바로 찾을 수 있습니다.
