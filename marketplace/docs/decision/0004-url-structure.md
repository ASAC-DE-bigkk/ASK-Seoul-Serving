# 0004 — URL 구조: 경로는 소비자로 가르고, 버전은 축마다 다른 곳에 둔다

- 상태: 초안 (합의 대기 · `D-5` 는 **미결**)
- 당사자: marketplace(@yooseongjin527) · K-Skill(@masondev1024) · MCP(@kang-gyeongmin) · 콘솔(@Exisign)
- 관련: ASK-Seoul-Serving#20(공개 배포 준비) · #32(MCP P0) · decision/0003(공개 식별자) ·
  ASAC-DAG#476 ②(URL 결정) · ASAC-DAG#642(경로 분리) · ASAC-DAG#638

## 왜

지금 네임스페이스가 셋인데 **가르는 축이 서로 다르다.**

| 경로 | 무슨 축으로 갈렸나 |
|---|---|
| `/api/*` | 시기 — "프로토타입" |
| `/v1/*` | 기술 계층 — "공용" |
| `/skill/v1/*` | 소비자 — "K-Skill 전용" |

이름만 봐서는 누가 무엇을 쓰는지 알 수 없고, `v1` 이 두 곳에 나오는데 뜻이 다르다
(`/v1` 은 API 판, `/skill/v1` 은 그 계약의 판). 여기에 `/mcp`(#32)가 붙으면 넷이 된다.

**지금 정하는 이유**: 공개 배포(#20) 직전이고, URL 은 소비자가 붙으면 못 바꾼다(#476 ②).
0003 이 "URL 에 무엇을 넣나"(식별자)를 정했다면 이 문서는 "URL 을 어떻게 가르나"(구조)다.

## 결정

### D-1. 경로는 **소비자 축**으로 가른다

```
/api/…      마켓플레이스 — 사람·일반 소비자 (카탈로그·미리보기·데이터·키)
/skill/v1/… K-Skill `seoul-urban-analytics` 전용
/mcp        MCP 클라이언트 전용 (POST 하나)
```

기술 계층("프로토타입/공용")이 아니라 **누가 쓰는가**로 가른다. `wrangler.toml` 의
`run_worker_first` 한 줄만 봐도 문이 몇 개고 주인이 누구인지 읽혀야 한다.

같은 데이터에 문이 여럿인 것은 중복이 아니라 **정책 차이**다 — 예컨대 `/skill/v1` 의 data 는
증거가 갖춰질 때까지 `503 product_not_ready` 로 닫혀 있고(#406), `/api/data` 는 열려 있다.
문을 합치면 그 차이를 표현할 자리가 없어진다.

**새 네임스페이스는 `run_worker_first` 등록이 먼저다.** 빠지면 요청이 워커에 닿지도 못하고
정적 404 로 떨어져 "경로가 없는 것처럼" 보인다.

### D-2. `/v1/*` 는 폐기한다 — 소비자가 0 이다

전수 확인(2026-08-04): ops-dashboard · sample · marketplace 자체 · k-skill 레포 **모두 0건**.
문서 안내도 `CLAUDE.md` 표 두 줄이 전부이고, `llms.txt` 는 스킬에게 *"공용 `/v1/*`와 별도이며
`/skill/v1` 만 쓰라"* 고 명시한다. 만들어만 두고 아무도 안 쓰는 표면이다.

`/v1` 이 주려던 것(제품 메타 한 번에 조립)은 **없어지지 않는다** — `/skill/v1/products/<id>` 와
MCP `describe_product` 가 각자 소비자에 맞는 모양으로 이미 준다. 공용 한 벌이 다시 필요해지면
그때 되살린다.

⚠️ **단독 판단이 아니다.** `/v1` 은 ASAC-DAG#642 안 B 로 팀이 정한 것이므로, 접기 전에 #642 에
"소비자 0" 실측과 함께 통지하고 이의가 없을 때 제거한다.

### D-3. `/skill/v1` 은 **그대로 둔다** — 대칭성 때문에 남의 계약을 바꾸지 않는다

`/skill` 로 줄여 셋을 나란히 맞추자는 안이 나왔으나 채택하지 않는다.

1. **공개된 남의 계약이다** — `skill-openapi.json`·`llms.txt` 에 실려 있고 소유자는
   @masondev1024 다. 미관 때문에 남의 공개 경로를 바꾸는 것은 0003 이 세운
   "URL 은 소비자가 붙으면 못 바꾼다"와 정면으로 어긋난다.
2. **그 `v1` 은 실제로 일한다** — 응답의 `registration_ready`·`blockers` 는 게시 게이트 판정
   계약이고, 증거 요건이 아직 정해지는 중이라(#406) 바뀔 여지가 크다. 바뀔 계약에는 판이 필요하다.
3. 아직 k-skill 레포가 안 붙었으니 "지금이 마지막 기회"로 보일 수 있는데, 그렇다면 **바꿀지
   말지는 소유자가 정한다.** 이 문서는 마켓플레이스가 그걸 요구하지 않는다는 것만 정한다.

### D-4. `/mcp` 는 **무버전**이다 — 버전이 이미 두 군데서 관리된다

MCP 는 축이 둘인데 **경로는 둘 다 담당하지 않는다.**

| 무엇의 버전 | 어디서 | 현재 값 |
|---|---|---|
| **프로토콜** 판 | `initialize` 응답의 `protocolVersion` (in-band 협상) | `2025-06-18` |
| **툴 계약** 판 | `initialize` 응답의 `serverInfo.version` | `0.1.0` |

경로에 `/mcp/v1` 을 두면 프로토콜 판이 두 곳에 생기고 둘이 어긋날 수 있다.

툴 계약은 MCP 가 대신 지켜주지 않지만, **깨지는 방식이 REST 와 다르다** — 클라이언트가 세션마다
`tools/list` 로 툴을 런타임에 발견하므로 모양에 고정돼 있지 않다. 그래서 규약을 이렇게 둔다.

- 툴 추가·입력 스키마 확장 → `serverInfo.version` **minor** 올림
- 툴 이름 변경·삭제·**의미 변경** → **major** 올림 + 옛 툴을 한동안 함께 둔다
- 파괴적 변경은 경로가 아니라 **새 툴 이름**으로 가른다 (`query_product` → `query_product_2`)

경로를 안 건드리는 실무적 이유도 있다 — MCP 클라이언트는 **URL 로 서버를 등록**하므로
`/mcp` → `/mcp/v2` 는 **모든 사용자가 설정을 다시 하는** 일이 된다. 툴 이름으로 가르면 설정은
그대로다.

`tools/list` 가 못 막는 것이 하나 있다: **이름·스키마가 그대로인데 의미만 바뀌는 경우.**
아무도 못 잡으므로 위 major 규칙이 그걸 덮는 유일한 장치다.

### D-5. 🔴 미결 — `/api` 에 판을 넣을 것인가

**이 문서에서 유일하게 안 정해진 항목이고, 셋 중 가장 급하다.** `/api/*` 는 판이 없는데
**가장 자주 바뀌는 표면**이다.

증거는 오늘 나왔다 — `/api/data/<식별자>` 의 의미를 테이블명에서 `product_id` 로 바꾸면서
(0003) 판이 없어 **별칭이라는 우회로**를 만들어야 했다. `/api/v1` 이 있었다면 `/api/v2` 로
가르면 될 일이었다.

| 안 | 뜻 | 대가 |
|---|---|---|
| **A. `/api/v1/*` 로 옮긴다** | 다음 파괴적 변경에 갈 곳이 생긴다 | 지금 문서·예시·`run_worker_first` 를 고쳐야 한다. 배포 전이라 소비자 파손은 0 |
| **B. 무판 유지 + 제약을 명문화** | 경로가 짧고 지금 할 일이 없다 | `/api` 는 앞으로 **추가만** 가능. 오늘 같은 의미 변경은 매번 별칭으로만, 그리고 별칭은 안 사라진다 |

배포 전이라 **A 의 비용이 앞으로 가장 싼 시점**이다. B 를 고르더라도 "무판으로 간다"를
결정으로 적어야 한다 — 안 적으면 다음 사람이 판이 있는 줄 알고 파괴적 변경을 시도한다.

## 정리 — 결정 후의 URL 표면

```
/api/…            마켓플레이스   판: D-5 미결
  POST·DELETE /api/keys · GET /api/catalog
  GET /api/preview/<product_id> · GET /api/data/<product_id> · GET /api/me

/skill/v1/…       K-Skill        판: 경로 (그대로)
  GET /skill/v1/bundles/seoul-urban-analytics
  GET /skill/v1/products/<product_id>[/data]

/mcp              MCP            판: initialize 응답 (경로 아님)
  POST /mcp

(정적)            사람           판 없음
  /docs /guide /catalog /status /support /legal /404
  /llms.txt /openapi.json /skill-openapi.json /column-docs.json /usage-patterns.json
```

식별자는 세 문 모두 **`product_id` 한 벌**이다(0003). MCP `query_product` 도 이미 그렇게
받는다 — 세 문이 같은 어휘를 쓴다.

그 파일과 세 줄을 되살리면 된다. 나머지는 규약이라 문서를 고치면 끝이다.
