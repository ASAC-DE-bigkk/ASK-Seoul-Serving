# 0002 — 페이지 합성 방식: partials 동기화기 (SSG 도입은 신호 대기)

- 상태: 초안 (멘토 검토 대기)
- 담당: marketplace/UI(@yooseongjin527)
- 관련: ASK-Seoul-Serving#30(다크 전환·팔레트 통일·partials) · #476 ①(공개 배포 게이트) ·
  CLAUDE.md §1 구성 · §6 구조 검토

## 왜

`public/` 의 8페이지는 머리(`<nav class="nav">`)와 바닥(`<footer>`)을 **각자 복제해서**
갖고 있었다. 실측(2026-08-03):

| | 값 |
|---|---|
| 페이지 | 8 (index · catalog · docs · guide · status · support · legal · 404) |
| nav 마크업 복제 | 7파일 (catalog 은 사이드바라 제외) |
| footer 마크업 | 6파일 **바이트 단위로 동일**, index 만 주석 1줄 차이 |

이 복제가 실제로 두 번 값을 물렸다.

1. **팔레트가 갈렸다.** 다크 리디자인이 자기 CSS 를 쓰는 index·catalog 에만 적용되고,
   `site.css` 를 쓰는 5페이지와 자기 CSS 를 쓰던 legal 은 구 라이트 테라코타
   (`--accent:#b8492a`)로 남았다. 사이트가 두 얼굴로 몇 커밋을 갔다.
2. **머리에 버튼 하나 넣는 데 7곳을 고쳐야 했다.** 테마 토글이 그랬다.

통증의 정체는 화면의 복잡도가 아니라 **복제**다. 그래서 프레임워크가 아니라 정본을
다룬다. (참고: 지금 규모는 8페이지 3,640줄이고, 진짜 상태를 가진 화면은 catalog 하나다.)

## 결정

### D-1. 머리·바닥의 정본은 `partials/`

`partials/nav.html` · `partials/footer.html` 이 정본이고, `npm run sync`
(`scripts/sync-partials.mjs`)가 7페이지의 해당 블록을 덮어쓴다. 페이지마다 다른 건
셋뿐이라 스크립트의 `PAGES` 표 한 곳에 모았다 — **활성 링크 · CTA · 바깥 폭**.

### D-2. 배포 경로에는 빌드 단계를 넣지 않는다 ← 이 문서의 핵심 경계

`public/` 은 지금도 앞으로도 **그대로 서빙되는 정본**이다(`wrangler.toml`
`[assets] directory = "public"`). 동기화기는 렌더러가 아니다:

- 결과물이 손으로 읽고 고칠 수 있는 HTML 이다 (고치면 D-3 이 잡을 뿐, 깨지지 않는다)
- 커밋 diff 에 최종 마크업이 그대로 드러난다 — 리뷰어가 산출물을 상상하지 않아도 된다
- `wrangler.toml` · `deploy-runbook.md` · 배포 절차를 **한 글자도 바꾸지 않았다**

`src/` → `dist/` 로 바꾸는 것, 즉 서빙되는 산출물을 생성물로 만드는 것은 이 선 너머다.
그건 §6 영역이고 멘토 게이트가 먼저다.

### D-3. 드리프트는 `npm test` 가 잡는다

`node scripts/sync-partials.mjs --check` 가 어긋난 페이지를 짚고 `exit 1` 한다.
**검사가 실제로 실패하는지 확인한 뒤에 채택했다** — 페이지 하나를 일부러 손으로
고쳐 exit 1 과 파일명 출력을 봤다. 늘 통과하는 검사는 없느니만 못하다.

### D-4. `catalog.html` 은 대상이 아니다

머리가 nav 가 아니라 사이드바(`.side`)다. 구조가 달라 억지로 한 partial 에 넣으면
`PAGES` 표에 분기가 생긴다 — 그건 S-3(아래) 신호이지 지금 할 일이 아니다.

## 검토한 대안

| 안 | 중복 제거 | 빌드 단계 | 탈락 이유 |
|---|---|---|---|
| **A. 아무것도 안 함** | ✗ | 없음 | 위의 사고가 이미 두 번. 세 번째를 기다릴 이유가 없다 |
| **B. 클라이언트 주입**(JS 로 nav 삽입) | ○ | 없음 | 머리가 sticky 라 주입 지연이 그대로 보인다. JS 없이 열면 탐색이 통째로 사라진다. 테마 FOUC 를 인라인으로 막아놓고 머리를 늦게 그리는 건 앞뒤가 안 맞는다 |
| **C. Worker 템플릿팅** | ○ | 없음 | 지금 HTML 은 Assets 가 서빙한다. Worker 가 모든 페이지 요청을 처리하게 만드는 건 서빙 모델 변경이고 `run_worker_first`·`not_found_handling` 과 얽힌다. 얻는 것에 비해 건드리는 게 크다 |
| **D. Astro / 11ty / Next** | ◎ | **생김** | 배포 경로에 빌드가 생긴다(D-2). 결정 문서 + 멘토 게이트 + runbook 개정이 선행. 지금 규모(8페이지)에는 과하다 |
| **E. 동기화기** ← 채택 | △ (드리프트만) | 없음 | 물리적 복제는 남는다. 대신 값이 거의 0이고, D 로 갈 때 partial 이 그대로 컴포넌트가 된다 |

## 비용

**지불한 것**

- 스크립트 97줄 + partial 2개(49줄), 새 디렉토리 `partials/`
- 규칙 하나가 늘었다: 생성 블록을 페이지에서 직접 고치지 않는다 (블록 첫 줄에 그렇게 적어뒀다)
- 리뷰어가 알아야 할 것 1개: "머리·바닥을 고칠 땐 partial + `npm run sync`"

**지불하지 않은 것**

- 빌드 산출물 · 번들러 · 의존성 추가 (`devDependencies` 는 여전히 wrangler 하나)
- `wrangler.toml` · `deploy-runbook.md` 변경
- 리뷰어의 프레임워크 학습 비용

**남는 부채 (숨기지 않는다)**

- 마크업 자체는 여전히 7파일에 물리적으로 존재한다. 없앤 건 **드리프트 위험**이지 중복이 아니다.
- `PAGES` 표는 조건이 늘면 템플릿 엔진 자작으로 미끄러지기 쉽다. 그 미끄러짐이 S-3 이다.
- 화면 로직 쪽 중복은 이 문서 밖이다 — catalog 15곳 · index 10곳 · status 4곳의
  `innerHTML` 문자열 조립은 그대로다.

## 이 결정을 뒤집는 신호

**둘 이상 켜지면 재검토한다.** 하나만으로는 움직이지 않는다 — 한 번의 불편은 대개
스크립트 몇 줄로 해결되고, 그렇게 해결하다 보면 어느새 SSG 를 자작하게 된다.

- **S-1** 페이지가 10개를 넘는다
- **S-2** partial 이 3개를 넘거나 서로 중첩해야 한다
- **S-3** `PAGES` 표에 조건 분기가 생긴다 (= 템플릿 엔진을 자작하기 시작했다는 뜻)
- **S-4** 상태를 가진 화면이 하나 더 붙는다 (예: `/skill/v1` 콘솔 — ASAC-DAG#642)
- **S-5** Worker ↔ UI 응답 타입을 공유해야 한다 (`_catalog` 행 모양이 지금은 문자열
  연결 안에만 있다)

## 신호가 오면 무엇을 고르나

지금 적어두는 이유: 신호가 왔을 때 조사를 처음부터 다시 하지 않기 위해서다.
**결론만 적고, 그때 다시 검증한다.**

**Astro(static 출력) + Tailwind v4 + TypeScript, `catalog` 만 React 아일랜드.**

- **Next.js 는 이 레포에서 틀린 답이다.** `/api/*`·`/v1/*` 를 서빙하는 Worker 가 이미
  제품 본체다(CLAUDE.md §1). Next 는 라우팅과 API 를 자기가 가지려 해서, 서버가 둘이
  되거나 Worker 를 route handler 로 이주시켜야 한다. 후자는 §2 불변 경계를 정면으로 건드린다.
- **Astro 를 static 으로 빌드하면** `[assets] directory` 가 `"public"` → `"dist"` 로
  한 줄 바뀌고 Worker 는 손대지 않는다. `run_worker_first` 도 그대로다.
- 8페이지 중 6개는 순수 문서라 JS 가 0바이트로 나간다. 진짜 인터랙션은 catalog 하나뿐이다.
- **Tailwind v4 는 CSS 변수 네이티브**라 지금 토큰이 그대로 옮겨간다(`:root` → `@theme`,
  `:root[data-theme="light"]` → `@custom-variant`). 이번 다크 작업은 버려지지 않는다.
- **shadcn/ui 는 쓰지 않는다.** 접근성 프리미티브(Radix)만 취한다. shadcn 의 값어치는
  제네릭 어드민 UI 를 빨리 만드는 것인데, 이 디자인은 단청 팔레트에 426칸 격자 히어로라
  오히려 싸운다.
- 한글 웹폰트를 쓰지 않는 결정(첫 화면 지연)은 프레임워크가 바꿔주지 않는다 — 그대로 간다.

## 롤백

**동기화기 폐기 — 비용이 사실상 0이다. 이게 이 안을 고른 결정적 이유다.**

`scripts/sync-partials.mjs` 와 `partials/` 를 지우고 `package.json` 의 두 줄
(`sync` · `test` 의 `--check`)을 되돌린다. `public/*.html` 은 손댈 필요가 없다 —
이미 그 자체로 완전한 HTML 이고 계속 그대로 서빙된다. 생성 블록 첫 줄의 안내 주석만
남는데, 지워도 그만이다.

**D(Astro)로 갔다가 되돌리기 — 비용이 대칭이 아니다.**

`dist/` 산출물을 `public/` 으로 커밋하면 서빙은 복구되지만, 사람이 읽으라고 쓴 주석과
손으로 다듬은 구조는 빌드 산출물에 남지 않는다. 되돌린 뒤의 HTML 은 지금 것보다 나쁘다.
**롤백 비용의 이 비대칭이 "신호 둘 이상"이라는 문턱을 세운 근거다.**
