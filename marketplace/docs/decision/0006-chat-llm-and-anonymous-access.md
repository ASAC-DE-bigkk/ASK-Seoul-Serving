# 0006 — 채팅의 LLM 호출처와 무인증 범위

- 상태: **제안** (2026-08-08, ASK-Seoul-Serving [#159](https://github.com/ASAC-DE-bigkk/ASK-Seoul-Serving/issues/159)) — 팀 결정 대기
- 관련: `src/mcp.js`(`TOOLS`), `src/index.js`(`handleRunPattern`), `wrangler.toml`, [0001 공유 계약](0001-shared-contracts.md)

## 맥락

#159 는 마켓플레이스에서 **사이트 안에서 바로 질문하고 답을 받는** 채팅을 제안한다. 담당 확인은 끝났고 두 담당이 방향에 동의했다.

- **MCP 담당(@kang-gyeongmin)** — `import { TOOLS }` + shared 핸들러 직접 재사용에 동의. 조건 둘: **`TOOLS` 는 읽기 전용**(툴 이름·스키마·설명은 MCP 계약의 정본이고 PlayMCP·외부 클라이언트가 이미 그 문구에 묶여 있다), **`callTool`/`handleMcp` 는 쓰지 않는다**(JSON-RPC 봉투·trace 가 섞인 MCP 전용 어댑터라 채팅은 자기 어댑터를 갖는다).
- **K-Skill 담당(@masondev1024)** — 채팅이 `/skill/v1` 을 부를 필요는 없고 **공통 실행 계층을 공유**하는 구조를 제안.

```text
agent-tools.js   공통 툴 스키마·실행
mcp.js           JSON-RPC·MCP 관측
chat.js          LLM 호출·채팅 정책
skill.js         K-Skill allowlist·추가 게이트
```

남은 것은 **비용과 정책에 걸린 결정 둘**이다. 둘 다 인프라 추가를 수반하므로 `CLAUDE.md` §6 에 따라 구현 전에 이 문서가 먼저다.

🔑 **설계 전제 하나를 먼저 못 박는다.** 이 채팅은 **LLM 이 SQL 을 짓지 않는다.** 도메인 오너가 게시·검증한 패턴(`run_pattern`, 실행 가능 428종)을 고르고 파라미터만 채운다 — MCP 가 이미 그렇게 하고 있고, 그게 kang 이 재사용을 환영한 이유다. 따라서 **LLM 에 요구되는 능력은 문장 생성이 아니라 도구 호출(function/tool calling)** 이다. 이 전제가 아래 ①의 판단 기준을 정한다.

## 결정 ① — LLM 을 어디서 부르나

### 후보

| | 안 | 형태 |
|---|---|---|
| **A** | Workers AI 바인딩 | `wrangler.toml` 에 `[ai] binding = "AI"`. 워커 안에서 호출 |
| **B** | 외부 LLM API | Anthropic·OpenAI 등. `wrangler secret` 으로 키 보관, 워커에서 fetch |
| **C** | LLM 없이 매칭만 | 질문 → 패턴 후보 제시. 사람이 고른다 |

### 비교

| 축 | A Workers AI | B 외부 API | C 매칭만 |
|---|---|---|---|
| 시크릿 | **없음** | API 키 1개 추가 |없음 |
| egress | **없음**(CF 내부) | 요청·응답마다 발생 | 없음 |
| 비용 모델 | 사용량 종량(CF 청구에 합류) | 종량 + egress | **0** |
| 되돌리기 | 바인딩 한 줄 제거 | 시크릿 폐기 + 코드 제거 | — |
| 품질 | 🔴 **미확인** — 한국어·툴 호출 | 검증된 편 | 해당 없음 |
| 답변 자연스러움 | 모델에 달림 | 좋음 | 없음(제품 목록만) |

### 권고 — **A 로 시작하고 B 를 열어 둔다**

**시크릿이 없는 쪽이 가장 싸고 가장 쉽게 되돌린다.** 우리는 비용 축에서 이미 두 번 데었다 — 하루 300GB 통신사 속도제한(원인은 수집이 아니라 dbt 전량 재빌드), 그리고 인프라 제안서에서 *"egress 는 무시 가능"* 이 **1,000배 틀렸던** 일. **"쓰면 얼마인지 모르겠는 것"을 기본값으로 두지 않는다.**

다만 A 는 **채택 전에 확인해야 할 조건이 하나 있다.**

> 🔴 **선택한 Workers AI 모델이 도구 호출(tool calling)을 지원하는가.** 위 설계 전제상 이게 안 되면 A 는 후보가 아니다. 프롬프트로 JSON 을 흉내 내게 하는 우회는 **쓰지 않는다** — 그건 "LLM 이 짓지 않는다"는 전제를 되돌리는 것이고, 이 채팅의 안전성이 거기서 나온다.

**C 는 기각하지 않고 폴백으로 남긴다.** A/B 어느 쪽도 못 쓰는 상황(비용 초과·장애·키 폐기)에서 채팅이 죽는 대신 **"이 질문에는 이 패턴들이 맞아 보입니다"** 로 내려앉게 한다. 이건 §5 부분 실패 강등 규약과 같은 모양이다.

### 확인 절차 (결정 전)

1. 후보 모델의 tool calling 지원 여부 — 지원 안 하면 A 탈락
2. 대표 질문 5개로 한국어 응답·툴 선택 실측 (제품 선택이 맞는가, 파라미터를 옳게 채우는가)
3. 질문 1건당 예상 비용과 **월 상한** 산정

## 결정 ② — 무인증 방문자에게 어디까지 여나

### 지금 있는 것

`GET /api/v1/preview/<id>` 가 **이미 무인증**이고 IP 버스트만 건다(`ip:` 버킷, 분당 60). 채팅에도 같은 패턴을 쓸 수 있다.

🔴 **다만 preview 와 채팅은 비용 성격이 다르다.** preview 는 D1 읽기라 사실상 공짜지만 **채팅은 호출마다 LLM 비용이 발생한다.** 그래서 IP 버스트만으로는 부족하다 — 버스트는 *"한 사람이 지금 얼마나"* 를 막지 *"오늘 전부 합쳐 얼마나"* 를 막지 못한다. NAT 뒤 공유·IP 회전도 IP 축의 한계다(0001 §값-최소화가 IP 를 저장하지 않는 것과 같은 이유로 정교한 IP 추적도 안 한다).

### 후보

| | 안 | 무인증 사용자 |
|---|---|---|
| **A** | 전면 무인증 | 제한 없이 채팅 |
| **B** | 키 필수 | 채팅 불가 — Google 로그인 후 |
| **C** | 맛보기 + 키 | 하루 N회·짧은 답변. 더 쓰려면 키 |

### 권고 — **C**, 단 상한을 두 층으로 건다

무인증을 완전히 닫으면(B) **처음 온 사람이 이 서비스가 무엇인지 알 방법이 없다.** 카탈로그·preview 를 무인증으로 연 것과 같은 판단이다. 반대로 A 는 비용 상한이 없다.

```text
① IP 버스트     기존 `ip:` 버킷 그대로 — 한 사람이 지금 미는 것
② 무인증 일일 총량  서비스 전체 합계 상한 — 오늘 전부 합쳐 쓸 수 있는 몫
```

**②가 핵심이다.** IP 당 상한은 총비용을 묶지 못한다. 전체 일일 상한을 두면 **최악의 날 비용이 예측 가능**해지고, 소진되면 채팅이 죽는 대신 결정 ①의 **C(패턴 매칭)로 내려앉는다.** 키 있는 사용자는 기존 일일 쿼터(1,000)를 그대로 쓴다.

무인증 몫이 소진됐을 때 화면은 **그렇게 말한다** — "오늘 체험 몫이 다 찼습니다. 로그인하시면 계속 쓰실 수 있어요." 조용히 실패하지 않는다.

## 관측 — 채팅 route 를 MCP 와 섞지 않는다

🔴 채팅이 부르는 툴은 **자기 route 값**을 남긴다(`chat_query_product` 등). MCP 값(`mcp_*`)에 섞으면 **[#162](https://github.com/ASAC-DE-bigkk/ASK-Seoul-Serving/issues/162) 가 정리한 축이 다시 흐려진다** — 화면 클릭이 MCP 사용량으로 세어지던 문제를 [PR#175](https://github.com/ASAC-DE-bigkk/ASK-Seoul-Serving/pull/175) 가 `run_pattern` / `mcp_run_pattern` 으로 가른 것과 같은 판단이다.

새 값은 **콘솔 `decision/0014` §1 표와 `ROUTE_KO` 에 같은 커밋에서** 반영한다. 배포가 반영보다 먼저 나간 사고(#132 → PR#138)가 그 규약의 존재 이유다.

## 대안과 기각

- **사용자가 자기 LLM 키를 넣는다(BYO)** — 비용은 0 이 되지만 방문자에게 키 두 개를 요구하게 된다. 처음 온 사람에게 채팅을 보이는 목적과 어긋난다. **나중 옵션으로만 남긴다.**
- **채팅이 `/skill/v1` 을 부른다** — K-Skill 은 제품 1종 allowlist 라 57종 중 1종만 보게 된다. K-Skill 담당도 필요 없다고 밝혔다. **같은 검증 계약을 공유하되 경로는 공유하지 않는다.**
- **`callTool`/`handleMcp` 재사용** — MCP 전용 어댑터라 JSON-RPC 봉투·trace 규약이 섞인다. MCP 담당이 명시적으로 선을 그었고, 이 선이 아래 「되돌리기」를 성립시킨다.

## 되돌리기

`chat.js` 라우트 제거 + `wrangler.toml` 바인딩(또는 시크릿) 제거. **`TOOLS`·shared 핸들러는 읽기만 하므로 MCP·K-Skill 표면에 영향이 0 이다** — kang 의 "읽기 전용" 조건을 지키는 실질적 이유가 이것이다. D1 스키마 변경이 없으므로 마이그레이션 되돌리기도 없다.

## 게이트 — 이 문서가 채택되기 전에 하지 않는 것

- `wrangler.toml` 에 AI 바인딩·LLM 시크릿을 추가하지 않는다
- `src/chat.js` 를 만들지 않는다
- `TOOLS` 를 수정하지 않는다 (읽기 전용 조건)

## 결과와 후속

채택되면 후속은 셋이다 — ① `agent-tools.js` 분리(현재 `mcp.js` 안에 있는 툴 정의·실행을 공용으로) ② `chat.js` 어댑터 ③ 콘솔 route 반영. ①은 MCP 동작을 바꾸지 않는 리팩터이므로 MCP 담당 리뷰 대상이다.

미결로 남는 것: 결정 ①의 모델 선정은 위 「확인 절차」 3단계 실측 뒤에 이 문서를 개정해 확정한다.
