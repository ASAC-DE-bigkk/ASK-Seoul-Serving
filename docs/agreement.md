## 1. 무엇을 만들고 있나

두 개의 Cloudflare Worker다. **다른 Worker · 다른 호스트**이고, 청중이 다르기 때문이다.

| | `marketplace/` | `ops-dashboard/` |
|---|---|---|
| 청중 | 외부 고객 · AI 에이전트 | 운영자 |
| 하는 일 | 키 발급 → 쿼터 → 카탈로그 게이트 → 조회 | 파이프라인·서빙 품질 관측 |
| 운영 호스트 | `ask-seoul.kr` | `ops.ask-seoul.kr` |
| 현재 상태 | 로컬 검증 완료, 배포는 멘토 게이트 | 로컬 전용 |

둘은 **같은 D1** 을 본다. 게이트웨이가 쓰는 표(`_keys`·`_request_log` 등)를 콘솔이 읽어야
하기 때문이다. 로컬에서는 `--persist-to` 로 같은 Miniflare 상태를 공유한다.

**공통 계약**(오류 형식·KST 경계·`key_hash`·`request_id`·값 최소화·증분 마이그레이션)의 정본은
[`marketplace/docs/decision/0001-shared-contracts.md`](../marketplace/docs/decision/0001-shared-contracts.md)
이고, 개정에는 상대 앱 담당 리뷰가 필요하다.

## 2. 🔴 `_request_log` — 이름 충돌 해소 (신규 합의)

### 무엇이 문제였나

운영·개발 D1 에 게이트웨이 정본과 **다른 스키마**의 `_request_log` 가 이미 있었다.

| | 원격에 실제로 있던 것 | 게이트웨이 정본 |
|---|---|---|
| 컬럼 | `ts` · `path` · `query` · `token` | `ts` · `route` · `table_name` · `status` · `key_hash` · `filters` · `row_count` · `ms` · `request_id` |
| 생성문 | `CREATE TABLE` (IF NOT EXISTS 없음) | `CREATE TABLE IF NOT EXISTS` |
| 데이터 | 2026-07-21~ (운영 389 · 개발 401행) | — |

`migrations/0002_request_log.sql` 이 `IF NOT EXISTS` 라 **다른 주체가 선점하면 조용히
넘어간다.** 그 상태로 배포하면 게이트웨이 INSERT 가 `ctx.waitUntil` 안에서 실패하고
**요청 로그가 전량 버려진다** — #23 에서 이미 한 번 겪은 형태다.

ASAC-DAG#681 교차 확인으로 파이프라인·dbt·대시보드는 전부 배제됐고,
한때 콘솔 쪽에서 표를 `_gw_request_log` 로 개명하려 했으나 **되돌렸다**(§9).

### ✅ 합의 (2026-08-04)

**`transit`·`citydata` 쪽에서 쓰고 있던 표이며, 운영자 협의를 통해 수정해도 된다는 응답을
받았다.** 따라서:

- **이름은 `_request_log` 그대로 간다.** 개명하지 않는다 — 게이트웨이·콘솔·문서·MCP 가
  전부 이 이름을 계약으로 쓰고 있고, 개명은 그 전부를 흔든다.
- **스키마 정본은 게이트웨이**(`marketplace/migrations/`)다. 기존 4컬럼 표는
  게이트웨이 스키마로 **정리한다.**
- 정리 절차는 §2-1. 기존 389~401행은 **보존 대상이 아니다**(수집 원칙상 남기면 안 되는
  `query`·`token` 값이 들어 있다 — §3 참조).
- **`0002_request_log.sql` 의 `IF NOT EXISTS` 는 명시적 충돌 검사로 바꾼다.** 같은 함정이
  다시 생기면 **숨기지 말고 멈춰야** 한다. 검사 스크립트는
  [`marketplace/scripts/check-request-log-schema.sql`](../marketplace/scripts/check-request-log-schema.sql).

### 2-1. 정리 절차 (배포 전 1회)

> ⚠️ **원격 D1 쓰기다.** 실행 전 팀에 알리고, 담당자가 직접 실행한다.

```bash
cd marketplace

# ① 지금 무엇이 있는지 확인 — verdict 가 'OK' 가 아니면 아래를 진행한다
npx wrangler d1 execute <D1> --remote --command \
"SELECT (SELECT group_concat(name,', ') FROM pragma_table_info('_request_log')) cols,
        (SELECT COUNT(*) FROM _request_log) rows"

# ② 기존 표를 치운다 — 값 보존 대상이 아니다(§3: query·token 은 남기면 안 되는 값)
npx wrangler d1 execute <D1> --remote --command "DROP TABLE IF EXISTS _request_log"

# ③ 정본 스키마로 다시 만든다 — 장부가 추적하므로 안 된 파일만 실행된다
npx wrangler d1 migrations apply <D1> --remote --env production

# ④ 재확인 — 'OK: 게이트웨이 스키마다' 여야 한다
npx wrangler d1 execute <D1> --remote --command \
"SELECT CASE WHEN (SELECT COUNT(*) FROM pragma_table_info('_request_log')
   WHERE name IN ('route','table_name','status','key_hash','filters','row_count','ms')) = 7
 THEN 'OK: 게이트웨이 스키마다' ELSE 'STOP: 아직 다른 표다' END verdict"
```

**이 절차가 §3(수집 축 확장)과 §7(공개 배포)의 선행 조건이다.** 정본이 안 선 상태에서
컬럼을 ALTER 로 얹으면 어느 표에 붙는지가 배포 순서에 좌우된다.

## 3. 수집 축 — 무엇을 남기고 무엇을 안 남기나

### 대원칙: **값이 아니라 축만**

`_request_log` 에는 **요청에 담긴 값과 응답 본문을 남기지 않는다.** 필터는 컬럼명만,
식별자는 `key_hash` 만. 원문 UA·전체 Referer·쿼리 값·이메일은 금지다.

> 이 원칙 때문에 위 §2 의 기존 4컬럼 표(`query`·`token`)를 보존하지 않는다.

### 3-1. 확정된 컬럼 (`migrations/0005` 한 물결)

ALTER 파일을 여러 번 내지 않기 위해 **#9 행동 로그 8종 + #3 intent + ASAC-DAG#642
패턴 키 2종 + env 1종**을 한 마이그레이션으로 묶는다. 전부 **nullable**, **추가만**
(삭제·개명 금지 — #78 D-3).

| 컬럼 | 무엇 | 근거 |
|---|---|---|
| `ua_class` | browser / ai_agent / ai_crawler / bot / cli / unknown | #9 ③ |
| `agent_name` | 에이전트 이름 (코드 상수 목록) | #9 ③ |
| `agent_mode` | crawler(수집) vs on_demand(사용자 대행) | #9 |
| `agent_verified` | **NULL 로 시작** — 검증 수단이 없다 ≠ 검증 실패 | #9 ④, #78 F-3 |
| `country` · `asn` | 남용 판정 축 (원문 IP 대신) | #9 ① |
| `referer_host` | 호스트만. 전체 Referer 아님 | #9 |
| `page_path` | 핵심 페이지 + 기계 문서 3종만 | #9 ② |
| **`intent`** | `X-ASK-Intent` 슬러그. **질문 원문 아님** | #3 오너 결정 |
| `pattern_id` · `publication_id` | 패턴 실행 API 로깅 키 | ASAC-DAG#642 |
| **`env`** | prod / dev / preview — 지표가 조용히 섞이는 것을 막는다 | 신규(§6) |

### 3-2. IP 축 — **(A) 미저장**

`ip_hash` **컬럼 자체를 만들지 않는다.** "안 모은 건 나중에 모을 수 있지만, 모은 건
되돌릴 수 없다"가 판단 기준이다. 남용 방어는 이미 버스트 제한·발급 rate limit 이 맡고
있고, IP 이력의 용도는 사후 분석뿐인데 그 수요가 아직 실증 전이다.

> **논의 경과**: 콘솔 쪽에서 "(B) 일 회전 솔트 해시"를 권고했으나(같은 ASN 안의 서로
> 다른 출처를 못 가른다는 이유), 게이트웨이 오너 결정은 **(A) 미저장** 이고 그것이 최종이다.
> "asn 으로 못 잡는 남용"이 실측되면 그때 (B) 로 승격한다 — 증분 규약상 ALTER 한 줄이다.

### 3-3. 발급 IP — 일 회전 솔트 해시 + 24h sweep

발급 rate limit(IP당 시간당 5회)은 IP 축이 필요해 완전 미저장이 불가능하다. 대신
`_issuance_log` 는 원문을 **일 회전 솔트 SHA-256** 으로 바꾸고 24시간 지난 행을 sweep 한다.
§3-2 와 합쳐 **원문 IP 가 어디에도 남지 않는다.**

`ISSUANCE_SALT` 미설정 시 발급은 **503 으로 닫힌다**(무염 해시 방지 — 의도된 fail-closed).

> 솔트 회전 경계에서 카운터가 리셋돼 이론상 상한 2배 통과 — 시간당 5회 상한이라 실해 없음.
> **인지하고 채택**했다.

### 3-4. 페이지 관측 범위

`/` · `/docs` · `/legal` + **`/llms.txt` · `/openapi.json` · `/column-docs.json`**.

뒤 3개가 핵심이다 — AI 여정의 **시작점**이 기계 문서 접근이고, 이게 관측에 없으면
`cli` 얼굴로 오는 에이전트를 여정으로 이을 수 없다. `/status` 는 제외(스스로 API 를 불러
이미 서빙 로그에 잡힌다).

### 3-5. 보관

**요청 로그 30일.** 샘플링은 보류한다 — 샘플링을 넣는 순간 "전체의 몇 %인가"를 못 세고
비율 지표가 먼저 죽는다. 페이지 행이 전체의 절반을 넘는 게 실측되면 **샘플링이 아니라
`route='page'` 만 짧은 보관(7일)으로 가른다.**

### 3-6. 질문 원문은 수집하지 않는다

멘토 제안("API 헤더에 질문 수집")에 대한 오너 결정: **의도 코드(슬러그)만 받는다.**

원문을 `_request_log` 에 넣으면 같은 행의 `key_hash`(↔이메일 1:1) 때문에 **"이메일에
연결된 개인 질의 이력"** 이 생긴다. 원문엔 PII 도 섞인다. 슬러그면 `filters` 와 같은
"축만" 철학이라 원칙이 무손상이다.

얻는 것: **`intent × row_count=0`** = "이 의도로 물었는데 빈 응답" — 커버리지 갭의 실측 신호.

원문 수집은 "intent 만으론 부족하다"가 데이터로 확인되면 **별도 테이블 + 익명화 + 짧은
보존 + `/legal` 갱신** 조건으로 재논의한다.

## 4. 운영 기록 — 파이프라인 관측을 콘솔이 소비한다

### 4-1. 정본은 ASAC-DAG, 콘솔은 읽기 전용 소비자

조회 DB 4종(`_ops_run_event` · `_ops_daily_metric` · `_ops_pipeline_state` ·
`_ops_pipeline_expectation`)의 스키마 정본은 `common/ops/d1_ops.py`(`ops-d1/v1`)다.
쓰는 쪽은 ASAC-DAG 의 관문(C-2)과 점검 적재기(C-3)뿐이다.

콘솔은 **읽기만** 한다. 집계를 대신 만들지 않는다 — 만드는 순간 정본이 둘이 되고 값이 갈린다.

### 4-2. 성공률 하나로 뭉개지 않는다 (D-7 3분류)

성공률 100% 인 7일 중 4일이 재발이던 실측이 근거다. 세 축을 **각각** 센다:

| | 운영 D1 실측 (2026-08-04, 14일) |
|---|---:|
| 정기 실행 통과 | 성공률 100% (14,301/14,363) |
| **수동 복구로 살림** (`retried_run_count`) | **210** |
| **빈 실행 = 초록 위장** (`empty_run_count`) | **3** |
| 행수 미측정 (`rows_unknown_count`) | **9,670** (측정 4,839) |

### 4-3. 모른다 ≠ 0 (F-3)

측정 못 한 값은 `NULL` 로 두고 화면도 "미확인"으로 구분한다. 0 으로 그리면 관측 공백이
"이상 없음"으로 위장된다.

- `layer` 는 **nullable 이 설계**다. 관문 이전 기록엔 단계 정보가 아예 없고, 없는 것을
  추측해 채우면 그게 거짓말이다. 단계별 합계에 넣지 않고 "단계 미기록 n건"으로 따로 센다
  (운영 실측 **1,364건**).
- `observation_state` = `complete` / `partial` / **`unverified`**.
  **`unverified` 는 "정상"이 아니라 "아직 점검이 안 지난 구간"** 이다. 초록으로 그리지 않는다.

### 4-4. 감시 3분류 — '감시 제외'와 '미등록'은 뜻이 정반대다

| 상태 | 뜻 | 판정 | 운영 실측 |
|---|---|---|---:|
| `watched` | 기대치 등록 + 감시 대상 | 침묵 한도(`max_delay_minutes`)로 판정 | 8 |
| `unmonitored` | `monitored=0` | **감시 제외** — 수동 전용. 안 도는 게 정상 | 1 |
| `unregistered` | 기대치 행 자체가 없음 | **미등록** — 판정 근거가 없다는 뜻이지 "이상 없음"이 아님 | **37** |

기대 주기가 **commerce 9건만** 등록돼 **DAG 37개가 판정 없이 돈다.** 경보로는 `watched` 의
멈춤 후보만 센다 — 미등록을 경보로 세면 등록 지연이 장애로 둔갑한다.

### 4-5. 신선도 — 조회 DB 는 실시간이 아니다

적재 DAG(`common_ops_d1_load`)는 **3시간 주기**다. 화면은 "마지막 반영 시각 + 경과"를
같이 쓰고, 주기의 1.5배를 넘기면 경고한다. 안 쓰면 실시간으로 읽혀 **없는 장애를 쫓는다.**

실시간 배선(C-2)은 보류 상태다 — 지연이 문제되면 그때 재결정한다.

### 4-6. 로그 원문 포인터

`_ops_run_event.log_bundle_key` = 그 run 의 텍스트 로그 tar.gz(R2) 위치. 번들이 하루 1회
뒤늦게 올라오므로 **당일 실행은 NULL 이 정상**이다.

콘솔은 경로만 보여주고 **링크로 만들지 않는다** — R2 자격증명이 없어 눌러도 안 열리는데,
그건 안 보여주는 것보다 나쁘다.

## 5. 소유 경계 — 누가 무엇을 고칠 수 있나

**남의 표를 만들거나 지우지 않는다.** 이 경계를 어기면 첫 스키마 수정이 남의 데이터를 지운다.

| 표 | 정본 | 게이트웨이 | 콘솔 |
|---|---|---|---|
| `_keys` · `_usage` · `_burst` · `_issuance_log` | **게이트웨이** | 전권 | 정해진 키 조치만 |
| `_request_log` | **게이트웨이** | 전권 | 읽기 전용 |
| `_ops_slo` · `_ops_domain` | **콘솔** | — | 전권 |
| `_ops_run_event` · `_ops_daily_metric` · `_ops_pipeline_state` · `_ops_pipeline_expectation` | **ASAC-DAG** (`d1_ops.py`) | — | 읽기 전용 |
| `_publication_ledger` · `_publication_log` | **ASAC-DAG** | — | 읽기 전용 |
| `_catalog` · 제품 표 `d1_*` | 도메인 export (`meta.serving` 계약) | 읽기 전용 | 읽기 전용 |

### 5-1. 마이그레이션은 증분 — DROP 금지

**항목 추가는 허용, 삭제·개명은 금지**(#78 D-3·D-6). 변경은 새 ALTER 파일로만.
파이프라인 정본(`d1_ops.py`)은 아예 `DROP TABLE` 을 만들지 않게 코드 수준에서 막혀 있고,
콘솔·게이트웨이도 같다.

> §2-1 의 `DROP TABLE _request_log` 는 이 규약의 **예외**다 — 우리 소유 표를 우리가 정리하는
> 것이고, 운영자 협의를 거쳤으며, 보존 대상이 아닌 값이 들어 있다(§3 원칙 위반 상태).
> 마이그레이션 파일이 아니라 **1회성 절차**로 실행한다.

### 5-2. 적용 여부의 정본은 D1 안의 장부

`wrangler d1 migrations apply` 가 안 된 파일만 실행한다. **새 파일은 `migrations/` 에
추가하면 끝이고 시드 체인에 나열하지 않는다** — 사람이 체인 갱신을 기억하던 시절
0004 누락으로 로컬 요청 로그가 몇 주간 전량 유실된 실사고가 있었다(#23).

장부 표는 **소유자별로 가른다** — 게이트웨이 `d1_migrations`, 콘솔
`d1_migrations_ops_dashboard`. 같은 D1 을 공유하므로 기본 이름을 쓰면 파일명이 겹치는 순간
(양쪽 다 `0002_*.sql` 가능) 한쪽이 "이미 적용됨"으로 조용히 건너뛴다.

### 5-3. 로컬 미러의 유일한 예외

콘솔 `migrations/0002` 는 조회 DB 4종의 **로컬 미러**다. 원격 없이 화면을 돌려보려면 빈
껍데기라도 있어야 해서 두되, 조건이 셋 붙는다:
① `CREATE TABLE IF NOT EXISTS` 만 — 팀 D1 에 이미 있으면 아무 일도 하지 않는다,
② DROP·ALTER 금지, ③ 미러는 소유 주장이 아니다 — 정본이 바뀌면 무조건 따라간다.

## 6. 환경 규약

### 6-1. 한 파일 안에서 갈린다

`wrangler.toml` 의 **기본 = 로컬**, `[env.production]` = 배포. `--env production` 을
**명시해야만** 선택되므로 플래그가 없으면 언제나 로컬이다 — 실수의 방향이 안전한 쪽으로 기운다.

⚠️ **env 섹션은 상속되지 않는다.** `assets`·`run_worker_first`·`vars`·`d1_databases` 를
두 곳에 같이 써야 한다.

| | 로컬/개발 | 운영 |
|---|---|---|
| D1 | `ask-seoul-dev-d1` (`9db0e851-…`) | `ask-seoul-prod-d1` (`59a8409e-…`) |
| 게이트웨이 | `:8787` | `ask-seoul.kr` |
| 콘솔 | `:8788` | `ops.ask-seoul.kr` |

**비밀값은 로컬은 파일(`.dev.vars`), 배포는 파일 밖(`wrangler secret put`).** 환경별 비밀
파일을 만들지 않는다 — `.dev.vars` 의 `dev` 가 이미 "개발 환경"을 뜻한다.

### 6-2. 🔴 환경이 섞인다 — 걸러 읽는다

실측(2026-08-04): 운영 D1 에 `environment='dev'` **17행**, 개발 D1 에 `'prod'` 63행.
도메인 쪽 판정 결함은 고쳐졌지만 **과거 행은 남는다.**

- 콘솔은 `ENV_SCOPE` 로 **운영 화면만** 좁힌다. 개발 화면에서까지 좁히면 "섞였다"는 사실
  자체가 안 보이는데, 그건 콘솔이 드러내야 할 관측이다.
- '환경' 카드에는 **언제나 전량**을 보여준다.
- `_request_log` 에는 그 축이 아예 없어 **`env` 컬럼을 §3-1 에 추가**했다.

**⚠️ 집계표(`_ops_daily_metric`)는 못 거른다** — `environment` 컬럼이 없다. 그래서 KPI 와
도메인×단계 매트릭스는 환경이 섞인 값이고, 화면이 그 사실을 직접 밝힌다.
컬럼 추가 여부는 [§10 C-2](#10-남은-과제와-담당).

## 7. 공개 배포 — 결정 4건

실제 `wrangler deploy` 는 **멘토 게이트**(ASAC-DAG#476 ①)다. 아래는 그 승인을 요청하기
위한 준비 상태다.

### 결정 A — 공개 서비스는 어느 D1 에 쓰는가

**✅ 확정: 팀 D1 1개 유지** (초기 제안이던 A-3 바인딩 분리는 철회).

- 설계가 단일 D1 이고, 정식 공개 시점에 prod 이관을 한다.
- ⚠️ **대가를 기록에 남긴다**: 통합 검증 기간 동안 **외부 이용자의 이메일·API 키가 팀 창고에
  쌓인다.** 리셋·마이그레이션 사고에 노출된다는 뜻이다
  ([배포 런북 §6](../marketplace/docs/deploy-runbook.md)).
- **콘솔 영향**: 단일 D1 이면 콘솔 이중 바인딩이 불필요하다. prod 이관 시점에 콘솔 바인딩도
  같이 움직인다.

### 결정 B — 운영 콘솔을 어떤 형태로 공개하는가

**✅ 확정: B-1 — 공개 시 전체를 Cloudflare Access 뒤로** (읽기 포함).

"읽기는 열고 조치만 잠근다"는 **로컬 전용이라는 전제 위의 설계**였고, 그 전제가 사라지면
같이 사라지는 게 맞다. 무인증 공개 시 노출되는 것(실측):

- `GET /api/keys` — 발급된 **전체 키 목록**(`key_hash` 64자·마스킹 이메일·상태·쿼터·사용량)
- `GET /api/summary` — 파이프라인 실패 이력, 멈춘 DAG 와 **담당자 GitHub 계정**,
  R2 실패 상세 경로, 환경 섞임 같은 팀 내부 사정

절차: `decision/0002`(로컬 전용)·`0004`(인증) 개정이 코드보다 먼저.
시점: 게이트웨이가 올라가 팀 D1 에 실사용 키·로그가 쌓이기 시작할 때. **다만 콘솔이
게이트웨이 배포를 막지는 않는다** — 공백 기간의 키 조치는 런북의 직접 쿼리로 버틴다.

> B-2(합성 데모 인스턴스)는 채택하지 않는다 — 콘솔의 존재 이유가 실측 관측이라 데모 가치가 반감된다.

### 결정 C — 공개 URL

**❌ 미결.** 게이트웨이 구조 채택(#476 ①)과 공개 URL 형태(workers.dev vs 커스텀 도메인,
`/v1` 경로 여부)가 아직이다. **한 번 공개한 URL 은 못 바꾼다** — 소비자가 붙으면 변경 = 파손.
배포보다 반드시 먼저 정해져야 하고, 콘솔까지 올리면 정할 주소가 둘이다.

함께 정리할 것: citydata 공개 워커가 **같은 데이터에 URL 2개**로 떠 있고(G4 '유일 창구'
위반), 그 워커는 파이프라인 D1 을 보고 있지 않다(카탈로그가 구 13종에서 멈춤).
새 창구를 여는 김에 정리하지 않으면 창구가 3개가 된다.

### 결정 D — 문의 창구

**❌ 미결.** `/legal` 이 "문의 창구도 열려 있다"고 안내하는데 외부인이 닿을 창구가 없다.
**팀 공용 메일 별칭 하나**가 최소선이라는 의견이 있었다. 이용자 삭제는 셀프 경로가 있어
막히지는 않는다.

## 8. MCP

AI 가 데이터를 **발견·이해·조회**하게 하는 **읽기 전용** MCP 서버.

| | |
|---|---|
| 전송 | **Streamable HTTP `POST /mcp` (stateless)**. stdio 는 로컬 개발·Inspector 용 |
| 위치 | marketplace Worker 안. 내부 HTTP 재호출이 아니라 **shared 함수·D1 바인딩 재사용**(인증·쿼터·로그 이중 집계 회피) |
| 인증 | **BYOK** — 사용자가 자기 키를 `Authorization: Bearer ask_…` 로 forward. 공용키·프록시 없음 |
| P0 툴 | `list_products` · `describe_product` · `preview_product` · `query_product` · `check_quota` |
| P1 | `run_pattern` (서버 실행 계약 확정 후) |
| 스코프 | 전 도메인 공개 제품. 단 **완비 보장은 V1 6제품 한정** — MCP 는 "verified bundle" 과 "general catalog" 를 구분해 노출 |

**정합성**: 제품 data · `_catalog` · support metadata 의 `publication_id` 가 **모두 같을 때만**
응답하고, 하나라도 어긋나면 **503 fail-closed**. MCP 는 503 을 "게시 정합성 일시 불일치 →
잠시 후 재시도"로 처리한다(빈손·실패가 아니다).

**커서**는 product·query·publication 에 결합된다 — 다른 publication 의 커서는 409 로 거절.

**키·로그 위생**: 로그·툴 응답·에러에 Bearer·email·원본 필터 값을 넣지 않는다.

**전송 프로토콜 정정 이력**: 초기 설계는 stdio 였으나 PlayMCP 가 원격에 Streamable HTTP 를
요구해 바꿨다. stateless 라 과거 SSE 재접속 루프(Worker API 폭증) 위험도 함께 회피된다.

**열린 항목**: 결정 C(공개 URL) 미정이라 **URI 하드코딩 불가** · 쿼터 조회 표면 확정 필요 ·
필터 값 discovery 수단 없음(`/v1` 에 preview·distinct-values 표면 없음).

머지분에서 재발했다. 머리·바닥의 정본은 `partials/` 이므로 `npm run sync` 한 번이면 되지만,

> 모든 PR 이 빨간불이 된다. CI 보다 이 정리가 먼저다.
