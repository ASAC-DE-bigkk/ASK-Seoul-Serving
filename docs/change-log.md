# 변경 이력

> **왜 이 문서가 있나** — 커밋 메시지는 *무엇을 바꿨나*를 적지만 **왜 그렇게 하기로 했나**는
> 이슈·PR 코멘트에 흩어진다. 시간이 지나면 "이건 왜 이 모양이지"에 답할 곳이 없어져
> 같은 논의가 다시 열리고, 이미 폐기한 안을 다시 시도하게 된다.
>
> **결정의 정본은 [`agreement.md`](agreement.md)** 이고, 이 문서는 **그 결정이 언제 무슨
> 의도로 코드에 닿았는지**를 시간순으로 남긴다. 둘은 역할이 다르다 —
> 저쪽은 "지금 무엇이 정해져 있나", 여기는 "어떤 순서로 어떻게 왔나".

## ⚠️ 이 문서 이전의 작업

**이 문서는 2026-08-04 에 처음 만들었다.** 그 전의 작업도 아래에 소급해서 적었지만,
**기록을 남기며 진행한 것이 아니라 뒤늦게 복원한 것**이다. 그래서:

- **실제로는 이뤄졌으나 여기 없는 작업이 있을 수 있다.** 특히 이 리포로 이관되기 전
  (`ask-seoul` 인프라 리포의 `serving-gateway/`·`ops-console/` 시절)과, 초기 며칠 사이의
  작은 변경들이 그렇다.
- 소급분의 **날짜는 커밋·이슈 시각 기준**이고, 그날 실제로 오간 논의 전부는 아니다.
- 빠진 것을 발견하면 **지우지 말고 추가**한다. 뒤늦게라도 남는 편이 낫다.

**2026-08-04 이후 항목은 작업과 함께 적는다** — 나중에 몰아 쓰면 의도가 이미 흐려져 있다.

### 🔴 콘솔 읽기를 잠근다 — 공개 URL 에 인증 없이 떠 있었다 (decision/0004 개정)

- **작업자**: @Exisign
- **의도 · 목표**: 실측으로 확인된 노출을 닫는다.

  ```
  https://ops.ask-seoul.kr/api/summary  → 200 · 운영 D1 실행 기록 98일치 · DAG 49건
  https://ops.ask-seoul.kr/api/keys     → 200 · 인증 없음
  ```

  `0004` 의 전제는 *"로컬 전용이라 노출 반경이 작다"* 였는데, `0015` 로 공개 배포되면서
  **그 전제가 사라졌다.** 같은 문서의 재검토 조건(*"공개 배포 시 Access 로 교체"*)이
  발동한 상태였는데 **그걸 이행하지 않고 배포만 했다** — 내 실수다.
- **왜 Access 가 아니라 워커 게이트인가**: 계정(`Dy950328@…`) 권한이 없다. 실측 403 —
  Access·WAF·IP 규칙·보안 수준 **전부**. Workers·D1·zone 읽기만 된다.
  **할 수 있는 것으로 먼저 막았다.** Access 는 여전히 필요하고 별건으로 남긴다.
- **조치**
  - `requireRead(env, request)` — `/api/*` **전부**. 라우터 **맨 앞 한 곳**에서 건다.
    라우트마다 붙이면 새 엔드포인트에서 빠뜨리고, 그게 곧 공개 노출이다.
  - 🔴 **fail-closed** — `OPS_TOKEN` 미설정이면 **읽기도 503**. 배포본은 시크릿을 넣기
    전까지 아무것도 안 낸다. "열린 채 잊히는 것"보다 "안 보여서 바로 아는 것"이 낫다.
  - `requireWrite` 와 **합치지 않았다** — 자물쇠는 같아도 문은 둘이어야 나중에 읽기만
    Access 로 넘길 수 있다.
  - `/api/trace` 예외 **철회** — "`request_id` 는 응답 받은 사람만 아는 난수"라 열어 뒀는데,
    콘솔 전체를 잠그는 마당에 구멍을 두면 그 구멍이 잊힌다.
  - 화면: 잠금 문구 교체, 401·503 이면 **조용한 새로고침이어도** 화면을 접고 잠금을 띄운다
    (안 그러면 만료된 채 옛 숫자가 계속 떠 있다).
- **🔴 잡은 것 — 화면 fetch 4곳이 토큰을 안 싣고 있었다**

  게이트만 넣고 끝냈으면 **드릴다운·API 상세·API 목록·요청추적이 전부 401** 로 깨질
  뻔했다. 호출 단위 감사(괄호 균형으로 잘라서 검사 — 줄 단위 grep 은 다중행을 잘못 본다)로
  찾아 7개 전부 `authHeaders()` 를 달았다.
- **결과 — 워커 진짜 코드를 태워 7경로 × 4상태 = 28건 확인**

  ```
  ① OPS_TOKEN 미설정      7경로 전부 503   (fail-closed)
  ② 설정 + 토큰 없음       7경로 전부 401
  ③ 설정 + 틀린 토큰       7경로 전부 401
  ④ 올바른 토큰            7경로 전부 게이트 통과
  ⑤ 정적 자산              워커 라우팅 밖 — 데이터는 안 나가고 잠금 화면만
  ```
- **문서**: [docs/access-control.md](access-control.md) 신규 — 레이어 4층(DNS·엣지·워커·데이터)
  별로 무엇을 막는지, 설정·확인 명령 실제 예제, **권한이 없어 못 하는 것**, 그리고
  **1인 프로젝트 재사용** 절.
- **되짚을 것**: PR 본문에 *"읽기 무인증인 채 공개됩니다"* 라고 **적어 두는 것으로

- **남긴 경계 — "쓰지 마라"는 걷었지만 "남의 표 모양은 바꾸지 마라"는 그대로**:
  `scripts/d1-query.mjs` 가 **DDL 을 전부 막는다**(대상 표 불문). 데이터 쓰기는 통과시키되
  남의 표면 경고를 찍는다. 스키마 변경은 `migrations/` + `npm run migrate` 로만.
- **🔴 검증 중에 잡은 것 — `0002` 를 운영에 돌릴 뻔했다**

  `migrations/0002` 는 조회 DB 4종의 **로컬 미러**였다. 운영에는 ASAC-DAG 가 만든 진짜
  표가 이미 있어 `CREATE TABLE IF NOT EXISTS` 는 무해하게 넘어가지만, **그 아래
  `CREATE INDEX` 3개가 `_ops_run_event`(19,832행, 남의 운영 표)에 실제로 만들어진다.**
  스키마 판단은 정본 소유자 몫이고, 라이브 표에 인덱스를 거는 비용도 그쪽 몫이다.

  기존 장부 백필 패턴으로 막았다 — **표가 이미 있으면 실행하지 않고 장부에만 적는다.**
  표가 없는 D1 에서는 그대로 실행돼 미러가 생기므로 두 경우 다 맞다.
- **🔴 검증 중에 잡은 것 ② — 연결이 틀렸는데 화면은 "운영을 보고 있다"고 답했다**

  "운영에 데이터가 없다"로 읽힌다.** 눈으로는 절대 못 잡는 종류다.

  | 시도 | 결과 |
  |---|---|
  | 맨 `wrangler dev --remote` | 전부 빈 결과 |
  | `--remote` + `preview_database_id` | 전부 빈 결과 |
  | **바인딩 `remote = true` + 플래그 없는 `wrangler dev`** | **정상** |

### 원격 D1 배포 전 검사(preflight) 신설

- **작업자**: @Exisign · 판정 수정 @yooseongjin527 (PR #55)
- **의도 · 목표**: `migrations apply` 는 되돌리기가 어렵다. prod D1 은 62개 제품이 사는
  파이프라인의 DB 이고 **D1 Time Travel 은 DB 전체를 덮어쓴다** — 제품 publish 하나를
  되돌리면 발급된 키·쿼터·요청 로그가 같이 과거로 간다. "일단 돌려 보고 되돌린다"가 성립하지
  않는다. 그리고 `CREATE TABLE IF NOT EXISTS` 는 **이름이 같으면 모양이 달라도 조용히 넘어간다.**
- **조치**: 표가 "있는지"가 아니라 **모양(컬럼)이 같은지**를 본다. 기대 모양은
  `migrations/*.sql` 을 **인메모리 sqlite 에 실제로 적용**해 뽑는다(하드코딩 드리프트 없음).
  `모양 다름`이면 종료 코드 1 로 중단하고, **사람이 정한 뒤 `--ack "<사유>"` 로만** 통과한다
  — `--ack` 는 판정을 바꾸지 않고 사유를 함께 찍는다.
- **결과**
  - 구현 중 셋에 부딪혀 전부 주석에 사유를 남겼다 — Windows `.cmd` 래퍼를 Node 20+ 가
    막는 것(CVE-2024-27980), D1 이 상관 참조 `pragma` 를 막는 것(`SQLITE_AUTH`),
    표 89개를 한 문장에 물으면 길이 한도에 걸리는 것(ASAC-DAG#677 과 같은 함정).
  - 🔴 **판정에 구멍이 있었다** — FOREIGN 을 "우리 컬럼을 **전부** 가져야 인수됨"으로 봐서
    **dev 의 부분 오염**(`request_id` 하나만 얹힌 상태)을 통과시켰다. **이 스크립트를 만든
    이유가 그 사고인데 정작 사고 난 DB 를 정상으로 판정하고 있었다.**
    @yooseongjin527 이 `baseline`(남의 표의 원래 모양)을 함께 두고
    `우리 컬럼 ∩ 실제 − baseline` 으로 보도록 고쳤다(PR #55). 받았다.

### 요청 로그 표 개명 — `_request_log` → `_gateway_request_log`

- **작업자**: @yooseongjin527 (PR #53) · 결정은 #44 전원 확인
- **의도 · 목표**: 운영·개발 D1 에 게이트웨이 정본과 **다른 스키마**의 `_request_log` 가 이미

  ALTER 도 하지 않는다**. 표 신설과 코드 전환을 **같은 커밋**에 — 30일 sweep
  `DELETE FROM _request_log` 가 코드 전환 없이 배포되면 transit 의 행을 지운다.
- **결과**
  - 🔴 이 과정에서 **`0004` 의 조건 없는 `ALTER` 가 이미 dev 의 남의 표에 얹혀 있던 것**이

    좌우된다"* 가 가정이 아니라 **일어난 일**이었고, 그게 개명의 결정적 근거가 됐다.

    공유하는데 한 문 이름을 붙이면 나머지 셋이 설명되지 않는다.
